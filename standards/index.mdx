Use this page to find the standards your BSV blockchain app follows and the site that holds each specification.

## The standards

<BlueTable>

| Standard | What it covers | Specification |
|----------|----------------|---------------|
| BRCs | Numbered specifications, called BSV Requests for Comments, for how wallets, apps and services work together, in categories such as wallet, transactions, payments and key derivation. | [`bsv.brc.dev`](https://bsv.brc.dev). A short link of the form `brc.dev/42` opens a BRC by its number. To propose a new BRC or discuss an existing one, see [Propose a BRC](/standards/brc-index/#propose-a-brc). |
| Wallet interface | <Hint tip="BSV Request for Comments 100, the standard interface between apps and wallets">BRC-100</Hint> is the interface between an app and a wallet. | The text is on [`bsv.brc.dev`](https://bsv.brc.dev/wallet/0100), and the standard has its own site at [`brc100.org`](https://brc100.org/). |
| Paymail | Handles that look like email addresses. On the BSV blockchain today, apps use Paymail to find which services a domain offers and to resolve a handle into an identity key. | The Bitcoin SV Technical Standards library, at [`tsc.bsvblockchain.org`](https://tsc.bsvblockchain.org/standards/paymail/). |
| Bitcoin protocol | The rules that decide whether a transaction or a block is valid, with the byte-exact specification, the Script opcodes, signature hashing and the upgrade history. | [`protocol.bsvblockchain.org`](https://protocol.bsvblockchain.org/) |
| Network Access Rules | The rules for the nodes on the BSV blockchain and their relationship with BSV Association. | [`nar.bsvblockchain.org`](https://nar.bsvblockchain.org/) |

</BlueTable>

## The protocol documentation and the Network Access Rules

The protocol documentation leaves out what does not affect validity, such as wallets and the network transport. The Network Access Rules are about nodes. Apps usually do not need to read either one while building.
