Use the BSV SDKs to create keys and transactions, or to call a user's wallet, from your own code in TypeScript, Go or Python. A Rust SDK is in development. The samples in the chooser create a key and print a testnet address, so you can run them without funds. If you have not sent a payment yet, start with [Send a payment from a web app](/get-started/quick-start-browser/).

## Choose your SDK

<SdkChooser />

<Visibility for="agents">

| Language | Package | Start with |
| --- | --- | --- |
| TypeScript | `@bsv/sdk` | [TypeScript SDK](/sdk/typescript/) |
| Go | `go-sdk` | [Go SDK](/sdk/go/) |
| Python | `bsv-sdk` | [Python SDK](/sdk/python/) |
| Rust | `rs-sdk`, in development, no release yet | [rs-sdk repository](https://github.com/bsv-blockchain/rs-sdk) |

Each sample creates a random key and prints its testnet address, with no network call.

```bash
npm install @bsv/sdk
```

```typescript
import { PrivateKey } from '@bsv/sdk'

const key = PrivateKey.fromRandom()
console.log(key.toPublicKey().toAddress('testnet'))
```

```bash
go get github.com/bsv-blockchain/go-sdk
go mod tidy
```

```go
package main

import (
	"fmt"
	"log"

	ec "github.com/bsv-blockchain/go-sdk/primitives/ec"
	"github.com/bsv-blockchain/go-sdk/script"
)

func main() {
	priv, err := ec.NewPrivateKey()
	if err != nil {
		log.Fatal(err)
	}
	address, err := script.NewAddressFromPublicKey(priv.PubKey(), false)
	if err != nil {
		log.Fatal(err)
	}
	fmt.Println(address.AddressString)
}
```

```bash
pip install bsv-sdk
```

```python
from bsv import Network, PrivateKey

key = PrivateKey()
print(key.address(network=Network.TESTNET))
```

## See each package in code

<Tabs>
<Tab title="WalletClient">

Your app asks a local <Hint tip="The standard interface between an app and a wallet">BRC-100</Hint> wallet, such as [BSV Desktop](/wallets/bsv-desktop/) or [BSV Browser](/wallets/bsv-browser/), to do the work, and `@bsv/sdk` is the place to start. Through `WalletClient`, the app finds the wallet on the user's machine, and the wallet keeps the keys and asks the user to approve each spend.

```typescript
import { WalletClient } from '@bsv/sdk'

// The second value is the name of your app, shown in the wallet's prompts
const wallet = new WalletClient('auto', 'example.com')
console.log(await wallet.getNetwork())
```

<Accordion title="Sample output">

```text
{ network: 'testnet' }
```

</Accordion>

<Callout type="info">
The `@bsv/simple/browser` package offers shortcuts for payments and tokens, such as `pay()` and `createToken()`, on top of these wallet calls. In version 0.7.0, `pay()` returns an empty `txid`, and `createWallet()` reports the network as `main` whatever network the wallet is on. To get the transaction ID, use `createAction` on `WalletClient`, and to read the network, use `getNetwork()`.
</Callout>

</Tab>
<Tab title="Wallet helper">

If you come from another chain, use `@bsv/wallet-helper` (beta) to describe outputs, scripts and change explicitly while the wallet still holds the keys and signs. It runs in the browser and in Node.

```typescript
import { WalletClient } from '@bsv/sdk'
import { TransactionBuilder } from '@bsv/wallet-helper'

const recipientAddress = '<testnet address>'

const wallet = new WalletClient('auto', 'example.com')
const { txid } = await new TransactionBuilder(wallet, 'Pay a testnet address')
  .addP2PKHOutput({ address: recipientAddress, satoshis: 1000 })
  .build()

console.log(txid)
```

<Accordion title="Sample output">

```text
1713a693288b5f9669ee48ca6fc471156e2d5dc6f9d47131f8a77610bb8d4daf
```

The wallet asks the user to approve the spend before the transaction ID prints.

</Accordion>

</Tab>
<Tab title="Server wallet">

A service, bot or test harness that owns its key, with no person approving each transaction, starts from `@bsv/simple/server`. The server entry point is part of the `@bsv/simple` package, so install that package:

```bash
npm install @bsv/simple
```

```typescript
import { ServerWallet } from '@bsv/simple/server'

const wallet = await ServerWallet.create({
  privateKey: process.env.SERVER_PRIVATE_KEY!,
  network: 'testnet',
  storageUrl: 'https://go-wallet-testnet-us-1.bsvblockchain.tech'
})
console.log(await wallet.getBalance())
```

<Accordion title="Sample output">

```text
{
  totalSatoshis: 0,
  totalOutputs: 0,
  spendableSatoshis: 0,
  spendableOutputs: 0
}
```

</Accordion>

The `storageUrl` above is BSV's testnet storage server. The public Wallet Infra endpoints, such as `store-us-1.bsvb.tech`, `store-eu-1.bsvb.tech` and `store-ap-1.bsvb.tech`, store Mainnet wallets, so on testnet use that server or your own deployment.

<Callout type="warning">
BSV recommends keeping wallet storage local when you can, with `Setup.createWalletSQLite` from `@bsv/wallet-toolbox`. Funding a server wallet from BSV Desktop does not work yet, and the payment is rejected with `The tx parameter must be valid AtomicBEEF`. A fix is in progress.
</Callout>

</Tab>
<Tab title="Wallet toolbox">

Implementing a wallet, extending its storage, building permission screens, or porting the wallet model to another language starts from `@bsv/wallet-toolbox`. The package ships the reference pieces: `Wallet`, `WalletStorageManager`, storage providers, `WalletSigner`, `Services`, `Monitor`, key managers, permissions, and test utilities such as `MockChain`. The [BRC-100 Wallet Interface](/concepts/wallet-model/) page explains the boundary between an app and a wallet.

```typescript
import { PrivateKey } from '@bsv/sdk'
import { Setup } from '@bsv/wallet-toolbox'

const key = PrivateKey.fromRandom()
const identityKey = key.toPublicKey().toString()

const { wallet } = await Setup.createWalletSQLite({
  env: {
    chain: 'test',
    identityKey,
    identityKey2: identityKey,
    filePath: 'wallet.sqlite',
    taalApiKey: '',
    devKeys: { [identityKey]: key.toHex() }
  },
  rootKeyHex: key.toHex(),
  filePath: 'wallet.sqlite',
  databaseName: 'my-wallet'
})

console.log(await wallet.getNetwork())
```

<Accordion title="Sample output">

```text
{ network: 'testnet' }
```

</Accordion>

An ordinary web app, or a backend agent with a private key, starts from one of the first three tabs.

</Tab>
<Tab title="SDK primitives">

Code that works with the primitives themselves, with nothing built on top of them, uses `@bsv/sdk` directly. It covers secp256k1 and secp256r1 cryptography, hashing, Script, transactions, <Hint tip="Background Evaluation Extended Format, a transaction sent with its proofs">BEEF</Hint> ([BRC-62](/concepts/spv/)), Merkle paths (BRC-74), BRC-42 key derivation, ARC broadcasting, and the BRC-100 interface types with wallet substrates.

```typescript
import { PrivateKey, P2PKH } from '@bsv/sdk'

const key = PrivateKey.fromRandom()
const address = key.toPublicKey().toAddress()
console.log(address, new P2PKH().lock(address).toASM())
```

<Accordion title="Sample output">

```text
1AB4wscnziNS6euaxcF39VrWW77SZh485A OP_DUP OP_HASH160 64a095f0148483a9c603de9255bd98ce066f3ab6 OP_EQUALVERIFY OP_CHECKSIG
```

</Accordion>

</Tab>

## Services and packages for other jobs

Some pieces are shared services you run or connect to, not packages you install:

<BlueTable>

| Service | What it does |
| --- | --- |
| [Wallet Infra](/wallet-dev/infrastructure/) | JSON-RPC storage and management of wallet UTXOs |
| [Message Box Server](https://bsv-blockchain.github.io/ts-stack/infrastructure/message-box-server/) | Peer-to-peer messaging with real-time WebSocket delivery |
| [Overlay Server](https://bsv-blockchain.github.io/ts-stack/infrastructure/overlay-server/) | Topic managers and lookup services for an overlay network |
| [UHRP Server](https://bsv-blockchain.github.io/ts-stack/infrastructure/uhrp-server-cloud-bucket/) | Production file storage on Google Cloud, addressed by content with <Hint tip="Universal Hash Resolution Protocol">UHRP</Hint> |
| [Wallet Abstraction Backend (WAB)](/wallet-dev/infrastructure/) | Multi-factor user authentication and key recovery, with SMS, ID verification and one-time codes |
| [Chaintracks Server](https://bsv-blockchain.github.io/ts-stack/infrastructure/chaintracks-server/) | <Hint tip="The reference implementation for managing BSV block headers">Chaintracks</Hint> keeps the block header chain and validates Merkle roots over REST |

</BlueTable>

For work beyond the starting points above, add the package built for it:

<BlueTable>

| You are building | Add |
| --- | --- |
| Messaging between users | `@bsv/message-box-client` with a Message Box Server |
| A token system | `@bsv/btms` and `@bsv/btms-permission-module` |
| An overlay node | `@bsv/overlay` and `@bsv/overlay-express` |
| An authenticated API | `@bsv/auth-express-middleware` |
| A payment-gated API | `@bsv/402-pay` (beta), set up in [Gate an API Behind Payments](/guides/payments/) |
| File storage | `@bsv/overlay-topics` (experimental) with a UHRP Server |

</BlueTable>
