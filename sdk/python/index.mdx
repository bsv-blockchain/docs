Use `bsv-sdk` to build BSV keys, scripts, transactions and proofs in Python, from a signed <Hint tip="Pay to Public Key Hash, the standard script that locks coins to an address">P2PKH</Hint> transaction up to broadcasting it to the network. The docs and examples live in the Python repositories, and this page links them.

## What the SDK includes

The package is `bsv-sdk` on PyPI, and you import it as `bsv`:

<BlueTable>

| Area | What you get |
| --- | --- |
| Keys and cryptography | `PrivateKey` and `PublicKey`, BIP32, BIP39 and BIP44 HD wallets, <Hint tip="BSV Key Derivation Scheme">BRC-42</Hint> key derivation, ECIES, Schnorr signatures and signed messages |
| Script and templates | `Script`, a script interpreter, and the `P2PKH`, `P2PK`, `OP_RETURN` and bare multisig templates |
| Transactions and fees | `Transaction`, `TransactionInput` and `TransactionOutput`, with fee calculation and change outputs |
| Proofs | <Hint tip="Simplified Payment Verification">SPV</Hint> checks with <Hint tip="Background Evaluation Extended Format (BRC-62), a transaction sent with its proofs">BEEF</Hint> and Merkle proofs |
| Broadcasting and chain tracking | Broadcasters such as <Hint tip="Authoritative Response Component, a transaction processor that tracks a transaction as the network processes it">ARC</Hint> and chain trackers |
| Wallet and authentication | Wallet substrates and serializers, and peer authentication with certificates |
| Overlay services and identity | Lookup and broadcast tools for <Hint tip="Built from topic managers, which decide what is admitted, and lookup services, which query what was admitted.">overlay services</Hint>, an identity client and a registry client |

</BlueTable>

## Get started

Install the SDK, then run a first script that signs a transaction without touching the network.

<Steps>
  <Step title="Install the SDK">
    This page was written against `bsv-sdk` 2.4.0, which needs Python 3.10 or newer. Install it with pip:

    ```bash
    pip install bsv-sdk
    ```

    pip also installs `pycryptodomex`, `requests`, `aiohttp` and `typing_extensions`.
  </Step>
  <Step title="Create sign.py">
    Create `sign.py` in your project folder. The script builds and signs a transaction on your computer, with a key, a <Hint tip="The part of a transaction output that sets the condition to spend it">locking script</Hint>, an input, an output and a signature. It makes no network call and spends no coins.

    <Callout type="warning">
      The script generates a private key on each run and never saves it. Keep a private key that holds real funds out of your source code and out of version control.
    </Callout>

    ```python sign.py
    import asyncio

    from bsv import Network, P2PKH, PrivateKey, Transaction, TransactionInput, TransactionOutput


    async def main():
        priv_key = PrivateKey()
        address = priv_key.address(network=Network.TESTNET)

        source_tx = Transaction(
            [],
            [TransactionOutput(locking_script=P2PKH().lock(address), satoshis=10000)],
        )

        tx_input = TransactionInput(
            source_transaction=source_tx,
            source_txid=source_tx.txid(),
            source_output_index=0,
            unlocking_script_template=P2PKH().unlock(priv_key),
        )
        tx_output = TransactionOutput(locking_script=P2PKH().lock(address), change=True)
        tx = Transaction([tx_input], [tx_output], version=1)

        tx.fee()
        tx.sign()

        print("Transaction ID:", tx.txid())
        print("Raw hex:", tx.hex())
        print("Scripts valid:", await tx.verify(scripts_only=True))


    asyncio.run(main())
    ```
  </Step>
  <Step title="Run the script">
    Run it from the same folder:

    ```bash
    python sign.py
    ```

    The script prints the transaction ID, the signed transaction in hex, and the result of the script check. The first two change on every run, because the key is new each time:

    ```text
    Transaction ID: 0ccd280ed6b5b4d49d7ac4593f3356b4a186fbca25a6996a66807b4c6c7fef78
    Raw hex: 0100000001d92fed6178372d43d2c1f6c5cc3b7d92d95872e0c7bdeba481156e00220c3c86000000006b48...
    Scripts valid: True
    ```
  </Step>
</Steps>

These parts of `sign.py` need a closer look:

- `priv_key.address(network=Network.TESTNET)` derives a testnet address from the key. If you leave out `network`, the address is a Mainnet address.
- The script builds its own source transaction with one output of 10,000 <Hint tip="The smallest unit of BSV. 100,000,000 satoshis make 1 BSV.">satoshis</Hint>, so the input has something to spend. To spend a real output, load the transaction that created one of your own <Hint tip="Unspent transaction output">UTXOs</Hint> instead.
- `change=True` makes the output take whatever the input holds beyond the fee, and `tx.fee()` calculates that fee.
- `verify(scripts_only=True)` runs the locking and unlocking scripts against each other, with no Merkle proof and no network. It is async, so the script runs inside `asyncio.run`.

To send a transaction, call `await tx.broadcast()`. With no argument it uses an ARC broadcaster for Mainnet. While you test, pass a testnet broadcaster, `tx.broadcast(default_broadcaster(is_testnet=True))`, with `default_broadcaster` imported from `bsv.broadcasters`. A broadcast transaction cannot be undone, so test on testnet before you use Mainnet.

## Find the docs and examples

The docs and examples live in the Python repositories, next to the code.

### Docs and repositories

Start from these repositories and docs:

- [py-sdk](https://github.com/bsv-blockchain/py-sdk), with its README and [releases](https://github.com/bsv-blockchain/py-sdk/releases).
- [py-sdk docs](https://github.com/bsv-blockchain/py-sdk/tree/master/docs), with a step-by-step tutorial, fee models, and ARC and <Hint tip="A transaction broadcaster for Teranode that is compatible with ARC">Arcade</Hint> broadcasting.
- [bsv-sdk on PyPI](https://pypi.org/project/bsv-sdk/), for versions and release history.
- [py-wallet-toolbox](https://github.com/bsv-blockchain/py-wallet-toolbox), with its [docs](https://github.com/bsv-blockchain/py-wallet-toolbox/tree/master/docs) and [examples](https://github.com/bsv-blockchain/py-wallet-toolbox/tree/master/examples), for building <Hint tip="BSV Request for Comments 100, the standard interface between apps and wallets">BRC-100</Hint> wallets in Python.

### Examples you can run

These single-file scripts in the [`examples` folder](https://github.com/bsv-blockchain/py-sdk/tree/master/examples) run on your computer without a network:

<BlueTable>

| Task | Script |
| --- | --- |
| Create HD wallets from a mnemonic | `hd.py` |
| Encrypt and decrypt with ECIES | `ecies.py` |
| Sign and verify a text message | `sign_text.py` |
| Derive keys with BRC-42 | `type_42.py` |
| Split a private key into 5 shares, any 3 of which recover it | `threshold_signature.py` |
| Write a custom fee model | `custom_fee_model.py` |

</BlueTable>
