Build transactions, keys and scripts by hand with `@bsv/sdk` when your code needs full control of each input, output and script. Work at this level when you write a custom script, sign with keys your code holds, or check transactions your app receives. An app that works through the user's wallet calls `createAction` on `WalletClient` instead, and the wallet does this work. To choose between the two, read [Use the TypeScript SDK](/sdk/typescript/). This page was written against `@bsv/sdk` 4.0.1.

## What your code takes on

Without a wallet, your code does each job a wallet would do. The SDK gives you a class for most jobs and leaves the bookkeeping to you:

<BlueTable>

| Job | What `@bsv/sdk` gives you | What stays with your code |
| --- | --- | --- |
| Keys | `PrivateKey` creates and loads keys, and `toAddress()` returns an address | Store each key outside your source code and version control |
| Inputs | Each input points at the output it spends, with a `sourceTransaction` and a `sourceOutputIndex` | Keep the full source transaction of every output you spend, since `fee()` throws an error when an input has none |
| Scripts | The <Hint tip="Pay to Public Key Hash, the standard script that locks coins to an address">`P2PKH`</Hint> and `RPuzzle` templates build a <Hint tip="The part of a transaction output that sets the condition to spend it">locking script</Hint> and the unlocking script that spends it | Write your own template for a condition these do not cover |
| Fee and change | `fee()` computes the fee with a fee model such as `SatoshisPerKilobyte`, and puts what is left in the outputs marked `change: true` | Call `fee()` before `sign()`, which throws an error while a change output has no amount |
| Broadcasting | `broadcast()` sends the signed transaction through a broadcaster class, such as `Teranode` | Check the `status` of the result, since a failed broadcast returns `status: 'error'` instead of throwing |
| Spent outputs | No store of your outputs | Record which <Hint tip="Unspent transaction output">UTXOs</Hint> you have spent, since two transactions that spend the same output cannot both confirm |
| Verification | `verify()` checks the scripts and follows each source transaction back to one with a `MerklePath`, and `Beef` packs a transaction with its proofs as <Hint tip="Background Evaluation Extended Format (BRC-62), a transaction sent with its proofs">BEEF</Hint> | Keep each transaction you receive with its source transactions and proofs, as BEEF, so that `verify()` can reach a mined transaction through <Hint tip="Simplified Payment Verification">SPV</Hint> |

</BlueTable>

[How transactions and fees work](/concepts/transactions/) explains how inputs, the fee and change fit together.

For cryptography without a transaction, `@bsv/sdk` also exports `Hash`, `ECDSA` and `Signature`, `Schnorr`, `SymmetricKey` for AES-GCM encryption, `PrivateKey.deriveSharedSecret` for ECDH, and `KeyDeriver` for BRC-42 key derivation.

## Calls that default to Mainnet

<Callout type="warning">
A transaction your code signs goes out with no approval step, and a blockchain transaction cannot be reversed. Test on testnet with the values below, and keep Mainnet keys out of test code.
</Callout>

Several calls fall back to Mainnet when you pass no argument. Pass the testnet value while you test:

<BlueTable>

| Call with no argument | What it uses | What to pass on testnet |
| --- | --- | --- |
| `key.toAddress()` | A Mainnet address, starting with `1` | `key.toAddress('testnet')`, which starts with `m` or `n` |
| `tx.fee()` | `LivePolicy`, which reads the rate from the policy of GorillaPool's Mainnet <Hint tip="The broadcast API that came before BSV Broadcaster. The ARC class of @bsv/sdk calls it">ARC</Hint> endpoint and falls back to 100 <Hint tip="The smallest unit of BSV. 100,000,000 satoshis make 1 BSV">satoshis</Hint> per kilobyte | A fee model with the rate of your endpoint, such as `new SatoshisPerKilobyte(1)` |
| `tx.broadcast()` | An `ARC` broadcaster for GorillaPool's Mainnet endpoint | `new Teranode('https://arcade-v2-testnet-us-1.bsvblockchain.tech/tx')`, the testnet endpoint of [BSV Broadcaster](/guides/services/broadcasting/) |
| `tx.verify()` | A `WhatsOnChain` chain tracker on Mainnet | `new WhatsOnChain('test')` |

</BlueTable>

Give `Teranode` the `/tx` address of the endpoint, as the BSV Broadcaster guide shows. The `ARC` class calls a path that BSV Broadcaster does not serve. The testnet endpoint of every other service is in [Network endpoints](/reference/networks/).
