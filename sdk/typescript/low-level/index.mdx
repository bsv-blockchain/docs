Build transactions, keys and scripts by hand with `@bsv/sdk` when your code needs full control of each input, output and script. Work at this level when you write a custom script, sign with keys your code holds, or check transactions your app receives. An app that works through the user's wallet calls `createAction` on `WalletClient` instead, and the wallet does this work. To choose between the two, read [Use the TypeScript SDK](/sdk/typescript/). This page was written against `@bsv/sdk` 4.0.1.

## What your code takes on

Without a wallet, your code does each job a wallet would do. The SDK gives you a class for most jobs and leaves the bookkeeping to you:

<BlueTable>

| Job | What `@bsv/sdk` gives you | What stays with your code |
| --- | --- | --- |
| Keys | `PrivateKey` creates and loads keys, and `toAddress()` returns an address | Store each key outside your source code and version control |
| Inputs | Each input points at the output it spends, with a `sourceTransaction` and a `sourceOutputIndex` | Keep the full source transaction of every output you spend, since `fee()` throws an error when an input has none |
| Scripts | The `P2PKH` and `RPuzzle` templates build a <Hint tip="The part of a transaction output that sets the condition to spend it">locking script</Hint> and the unlocking script that spends it | Write your own template for any other spending condition |
| Fee and change | `fee()` computes the fee with a fee model such as `SatoshisPerKilobyte`, and puts what is left in the outputs marked `change: true` | Call `fee()` before `sign()`, which throws an error while a change output has no amount |
| Broadcasting | `broadcast()` sends the signed transaction through a broadcaster class, such as `Teranode` | Check the `status` of the result, since a failed broadcast returns `status: 'error'` instead of throwing |
| Spent outputs | No store of your outputs | Record which <Hint tip="Unspent transaction output">UTXOs</Hint> you have spent, since two transactions that spend the same output cannot both confirm |
| Verification | `verify()` checks the scripts and follows each source transaction back to one with a `MerklePath`, and `Beef` packs a transaction with its proofs as <Hint tip="Background Evaluation Extended Format (BRC-62), a transaction sent with its proofs">BEEF</Hint> | Keep the proofs of the transactions you receive, so that <Hint tip="Simplified Payment Verification">SPV</Hint> can reach a mined transaction |

</BlueTable>

How inputs, the fee and change fit together is explained in [How transactions and fees work](/concepts/transactions/).

## Calls that default to Mainnet

<Callout type="warning">
A transaction your code signs goes out with no approval step, and a blockchain transaction cannot be reversed. With no argument, `broadcast()` sends to Mainnet. Test on testnet, pass a testnet broadcaster, and keep Mainnet keys out of test code.
</Callout>

Several methods pick a network service when you pass no argument, and each default points at Mainnet. Pass the testnet value while you test:

<BlueTable>

| Call with no argument | What it uses | What to pass on testnet |
| --- | --- | --- |
| `key.toAddress()` | A Mainnet address, starting with `1` | `key.toAddress('testnet')`, which starts with `m` or `n` |
| `tx.fee()` | `LivePolicy`, which reads the rate from the policy of GorillaPool's Mainnet <Hint tip="A transaction broadcast service. The ARC class of @bsv/sdk talks to it">ARC</Hint> endpoint and falls back to 100 <Hint tip="The smallest unit of BSV. 100,000,000 satoshis make 1 BSV">satoshis</Hint> per kilobyte | A fee model with the rate of your endpoint, such as `new SatoshisPerKilobyte(1)` |
| `tx.broadcast()` | An `ARC` broadcaster for GorillaPool's Mainnet endpoint | A `Teranode` broadcaster with a testnet endpoint of BSV Broadcaster |
| `tx.verify()` | A `WhatsOnChain` chain tracker on Mainnet | `new WhatsOnChain('test')` |

</BlueTable>

To send through BSV Broadcaster, give `Teranode` the `/tx` address of the endpoint, as [Broadcast transactions with BSV Broadcaster](/guides/services/broadcasting/) shows. The `ARC` class calls a path that BSV Broadcaster does not serve.
