Pick the `@bsv/*` package that adds messaging, API authentication, payments or an <Hint tip="A service that indexes an app's transactions. Topic managers decide which outputs it admits, and lookup services answer queries about them">overlay service</Hint> to an app built on `@bsv/sdk`, and see what each one does and its status.

## Before you choose a package

Start with `@bsv/sdk` and add the package your app needs next to it. In your project folder, run, for example:

```bash
npm install @bsv/sdk @bsv/wallet-helper
```

The packages declare Node.js 22 or newer, and this page was written against `@bsv/sdk` 4.0.1. Two other pages can settle the choice first:

- To choose between `@bsv/sdk`, `@bsv/simple` and the other packages, see the [SDKs overview](/sdk/).
- To build a wallet instead of an app, see [Build a wallet with wallet-toolbox](/wallet-dev/wallet-toolbox/).

## Find the other packages by task

The rows link to the package folder in [ts-stack](https://github.com/bsv-blockchain/ts-stack), the repository that holds the TypeScript stack. The status is the maturity that ts-stack and the package README give it. A stable package has a locked API. A beta package can still change its API. An experimental package is in early development. The versions are the latest published on npm on 2 November 2026.

### Authenticate and charge the callers of an API

To know which user calls your Express API, start from the [Authenticate users with their wallet](/guides/identity-auth/) guide. To charge for routes, the [Gate an API behind payments](/guides/payments/) guide uses [`@bsv/402-pay`](/sdk/packages/402-pay/).

<BlueTable>

| Package | Version | Status | What it does |
| --- | --- | --- | --- |
| [`@bsv/auth-express-middleware`](https://github.com/bsv-blockchain/ts-stack/tree/main/packages/middleware/auth-express-middleware) | 2.3.0 | Stable | Express middleware for <Hint tip="BSV Request for Comments 103, mutual authentication between two peers">BRC-103</Hint> mutual authentication. It handles the handshake, verifies each authenticated request and signs the response. |
| [`@bsv/payment-express-middleware`](https://github.com/bsv-blockchain/ts-stack/tree/main/packages/middleware/payment-express-middleware) | 2.1.11 | Stable | Express middleware that answers with an HTTP 402 challenge and checks the payment. It runs after `@bsv/auth-express-middleware` and uses the earlier `x-bsv-payment` flow, a different protocol from the <Hint tip="BSV Request for Comments 121, Simple 402 Payments">BRC-121</Hint> flow of `@bsv/402-pay`, so choose one of the two for an API. |
| [`@bsv/auth`](https://github.com/bsv-blockchain/ts-stack/tree/main/packages/middleware/auth) | 0.1.8 | Beta | Wallet login that does not depend on a web framework. The wallet signs a short-lived proof that it controls an identity key, and the server verifies it and accepts it once. |

</BlueTable>

### Authenticated sockets and Paymail

Open an authenticated Socket.IO connection between a client and a server, or add <Hint tip="A handle that resolves to a user's identity key. Its domain lists the Paymail services it supports">Paymail</Hint> support to an Express app, with:

<BlueTable>

| Package | Version | Status | What it does |
| --- | --- | --- | --- |
| [`@bsv/authsocket`](https://github.com/bsv-blockchain/ts-stack/tree/main/packages/messaging/authsocket) | 2.1.11 | Stable | Server side of Socket.IO with BRC-103 mutual authentication on every connected client. |
| [`@bsv/authsocket-client`](https://github.com/bsv-blockchain/ts-stack/tree/main/packages/messaging/authsocket-client) | 2.1.10 | Stable | Client side of the same Socket.IO connection. It signs outbound messages and verifies inbound ones. |
| [`@bsv/paymail`](https://github.com/bsv-blockchain/ts-stack/tree/main/packages/messaging/ts-paymail) | 2.4.12 | Stable | A Paymail client and an Express router for capability discovery, public profiles and transaction delivery. |

</BlueTable>

### Build an overlay

[`@bsv/overlay-express`](/sdk/packages/overlay-express/) runs an overlay service and builds on `@bsv/overlay` and `@bsv/overlay-discovery-services`. The packages below are the pieces to use on their own or to add to it. To see how an overlay works, read [How overlays work](/concepts/overlays/). To use one in an app, follow [Track transactions with overlays](/guides/overlays/).

<BlueTable>

| Package | Version | Status | What it does |
| --- | --- | --- | --- |
| [`@bsv/overlay`](https://github.com/bsv-blockchain/ts-stack/tree/main/packages/overlays/overlay) | 2.7.0 | Stable | The engine of an overlay service. It admits transactions through topic managers, keeps the state of the outputs and serves lookup services. |
| [`@bsv/overlay-topics`](https://github.com/bsv-blockchain/ts-stack/tree/main/packages/overlays/topics) | 2.0.3 | Experimental | Topic managers and lookup services for protocols such as identity certificates, key and value storage, message boxes and file storage. |
| [`@bsv/overlay-discovery-services`](https://github.com/bsv-blockchain/ts-stack/tree/main/packages/overlays/overlay-discovery-services) | 2.2.9 | Stable | The <Hint tip="Services Host Interconnect Protocol">SHIP</Hint> and <Hint tip="Services Lookup Availability Protocol">SLAP</Hint> services that let overlay nodes advertise the topics they host and the lookup services they offer. |
| [`@bsv/gasp`](https://github.com/bsv-blockchain/ts-stack/tree/main/packages/overlays/gasp-core) | 1.3.10 | Stable | The Graph Aware Sync Protocol. It synchronizes transaction data between two parties. Each side fetches only what it does not have and validates what it receives. |

</BlueTable>

### Build transactions and connect wallets

To build transactions or connect your app to a wallet, pick from:

<BlueTable>

| Package | Version | Status | What it does |
