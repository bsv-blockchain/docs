Use this reference to check what `@bsv/sdk` needs from the JavaScript environment you target, such as Node.js, a browser app built with a bundler, a plain web page, a worker or React Native, and how to load it there. Read this before you add the SDK to a new kind of project, or when the SDK raises an error about randomness or HTTP that it does not raise elsewhere. This page was written against `@bsv/sdk` 4.0.1.

## What the SDK needs

`@bsv/sdk` has no runtime dependencies and does not use the Node.js `Buffer`. It asks the runtime for three things:

<BlueTable>

| Need | What the SDK uses | Used for |
| --- | --- | --- |
| A module loader | An ES module build (`dist/esm`), a CommonJS build (`dist/cjs`) and a UMD bundle (`dist/umd/bundle.js`) | Loading the package in any of the environments below |
| Secure random numbers | `crypto.getRandomValues` of the global object, `self` or `window`, or else `randomBytes` from `node:crypto` | Generating keys, such as `PrivateKey.fromRandom()`, and the random values used in encryption, such as ECIES |
| HTTP requests | The global `fetch`, or else the `node:https` module when the code runs as CommonJS | Broadcasting transactions and calling services such as WhatsOnChain |

</BlueTable>

Building, signing and verifying a transaction need neither randomness nor HTTP.

## Environments

<BlueTable>

| Environment | How to load it | What to check |
| --- | --- | --- |
| Node.js 22 or newer | `import` from `@bsv/sdk` (ES modules) or `require('@bsv/sdk')` (CommonJS) | The package declares `"node": ">=22"` in its `engines` field. See [Install the SDK in Node or React](/sdk/typescript/setup/) |
| Browser app with a bundler, such as Vite | `import` from `@bsv/sdk` | The bundler picks the ES module build. No polyfill is needed |
| Web page without a bundler | `<script src="bundle.js">` with the file `dist/umd/bundle.js` of the package | The bundle defines the global `bsv`, such as `bsv.PrivateKey` |
| Web Worker | `import` from `@bsv/sdk` in a module worker | Workers expose `crypto.getRandomValues` and `fetch` on `self`, which the SDK reads |
| React Native | `import` from `@bsv/sdk` | If the runtime has no `crypto.getRandomValues`, install a polyfill that defines it and import it before `@bsv/sdk` |

</BlueTable>

To reach the user's wallet from these environments, `WalletClient` tries its substrates in turn and uses the first that answers, such as the HTTP port of [BSV Desktop](/wallets/bsv-desktop/) or the React Native WebView bridge. See [Connect to a wallet with WalletClient](/sdk/typescript/wallet-client/).

## Troubleshooting

<AccordionGroup>
  <Accordion title="Key creation throws because the runtime has no secure random source" defaultOpen>
    The error is `No secure random number generator is available in this environment.`. The runtime has no `crypto.getRandomValues` and no `node:crypto`, so `PrivateKey.fromRandom()` and any other call that needs randomness throw this error. In React Native, install a polyfill for `crypto.getRandomValues` and import it before `@bsv/sdk`. In other runtimes, check that the global `crypto` object is not removed or replaced.
  </Accordion>
  <Accordion title={<>Broadcast returns code 500 "Internal Server Error" before reaching the server</>}>
    The ARC, Teranode and WhatsOnChain broadcasters return `{ status: 'error', code: '500', description: 'Internal Server Error' }` when its HTTP request throws before it reaches the server. One cause is a runtime with no `fetch` that loads the SDK as an ES module, where the `node:https` fallback is not available. Provide a global `fetch`, or pass an HTTP client of your own to the broadcaster. The same result can also come from the server itself, so check the network log first.
  </Accordion>
</AccordionGroup>
