Look up the explorer, <Hint tip="A site that sends free test coins to an address">faucet</Hint>, broadcast endpoint, wallet storage and address format of each BSV network. Use it when you point code, a wallet or a test script at a network, and take every value from the same row. What each network is for, and the name each package gives it, is in [How BSV networks differ](/concepts/networks/).

This page was written against `@bsv/sdk` 4.0.1 and `@bsv/wallet-toolbox` 2.15.1. Every endpoint on it was checked on 3 November 2026.

## Endpoints by network

Each row is one value of `chain` in `@bsv/wallet-toolbox`. The broadcast column lists the public <Hint tip="The BSV Association's transaction broadcaster, which takes a signed transaction over HTTP and follows it until it is mined">BSV Broadcaster</Hint> endpoint of the network:

<BlueTable>

| Network | Explorer | Faucet | BSV Broadcaster | Wallet storage | Address starts with |
| --- | --- | --- | --- | --- | --- |
| Mainnet, `main` | [whatsonchain.com](https://whatsonchain.com/) | None | `https://arcade-us-1.bsvblockchain.tech` | `https://storage.babbage.systems` | `1` |
| testnet, `test` | [test.whatsonchain.com](https://test.whatsonchain.com/) | [bsvfaucet.com](https://bsvfaucet.com/) | `https://arcade-v2-testnet-us-1.bsvblockchain.tech` | None public, see [Wallet storage](#wallet-storage) | `m` or `n` |
| teratestnet, `ttn` | Not published | [faucet-ttn.bsvblockchain.tech](https://faucet-ttn.bsvblockchain.tech/) | `https://arcade-v2-ttn-us-1.bsvblockchain.tech` | `https://staging-storage.babbage.systems` | `m` or `n` |
| `stn` | None public | None public | You set `STN_ARCADE_URL` | None public | No `toAddress` option |
| `tstn` | None public | None public | You set `TSTN_ARCADE_URL` | None public | No `toAddress` option |
| `regtest` | None public | None public | You set `REGTEST_ARCADE_URL` | None public | No `toAddress` option |
| `mock` | No network | No network | No network, use `MockServices` | No network | No `toAddress` option |

</BlueTable>

For `stn`, `tstn` and `regtest`, `@bsv/wallet-toolbox` reads the broadcaster address from the environment variable in the table. It reads the block header service from `STN_CHAINTRACKS_URL`, `TSTN_CHAINTRACKS_URL` or `REGTEST_CHAINTRACKS_URL`, and uses `/chaintracks/v1` on the broadcaster host when that variable is unset.

## Broadcast endpoints

The public BSV Broadcaster endpoints need no API key. Each one answered `GET /health` with `"healthy":true`:

<BlueTable>

| Network | Endpoint |
| --- | --- |
| Mainnet | `https://arcade-us-1.bsvblockchain.tech` |
| Mainnet | `https://arcade-v2-us-1.bsvblockchain.tech` |
| Mainnet | `https://arcade-eu-1.bsvblockchain.tech` |
| Mainnet | `https://arcade.gorillapool.io` |
| testnet | `https://arcade-v2-testnet-us-1.bsvblockchain.tech` |
| teratestnet | `https://arcade-v2-ttn-us-1.bsvblockchain.tech` |

</BlueTable>

<Callout type="warning">
A transaction sent to a Mainnet endpoint spends real BSV, and a blockchain transaction cannot be reversed. Check the network of the endpoint before your code sends anything.
</Callout>

How to submit to these endpoints, and which SDK class to use, is in [Broadcast transactions with BSV Broadcaster](/guides/services/broadcasting/).

### Defaults in the packages

When your code does not name a broadcaster, the packages pick one by network:

<BlueTable>

| Network | `@bsv/sdk` | `Services` in `@bsv/wallet-toolbox`, in the order it tries them |
| --- | --- | --- |
| Mainnet | `https://arc.gorillapool.io` | `https://arc.gorillapool.io`, then `https://arc.taal.com`, then Bitails at `https://api.bitails.io/`, then WhatsOnChain |
| testnet | `https://testnet.arc.gorillapool.io` | `https://arc-test.taal.com`, then Bitails at `https://test-api.bitails.io/`, then WhatsOnChain |
| teratestnet | None | `https://arcade-v2-ttn-us-1.bsvblockchain.tech` only |

</BlueTable>

- In `@bsv/sdk`, `tx.broadcast()` with no argument always sends to the Mainnet address. The testnet address comes from `defaultBroadcaster(true)`. Both are <Hint tip="The broadcast API that came before BSV Broadcaster">ARC</Hint> endpoints.
- In `@bsv/wallet-toolbox`, pass `arcadeUrl` to `createDefaultWalletServicesOptions` to put a BSV Broadcaster endpoint first on Mainnet or testnet.

## Explorer API

Each public network has a WhatsOnChain API for transactions, addresses and block data. Each base answered `GET /chain/info`:

<BlueTable>

| Network | API base | `chain` in the answer |
| --- | --- | --- |
| Mainnet | `https://api.whatsonchain.com/v1/bsv/main` | `main` |
| testnet | `https://api.whatsonchain.com/v1/bsv/test` | `test` |
| teratestnet | `https://api.woc-ttn.bsvblockchain.tech/v1/bsv/test` | `teratestnet` |

</BlueTable>

The teratestnet API keeps `test` in its path. The `WhatsOnChain` class of `@bsv/sdk` accepts `'main'` and `'test'`, and the `Services` class of `@bsv/wallet-toolbox` calls WhatsOnChain only on Mainnet and testnet.

## Wallet storage

`Setup.createWalletClientNoEnv` in `@bsv/wallet-toolbox` uses `https://storage.babbage.systems` when `chain` is `main`, and `https://staging-storage.babbage.systems` for every other chain. Each server names its network on its home page:

<BlueTable>

| URL | Home page text |
| --- | --- |
| `https://storage.babbage.systems` | `BRC-100 mainNet Storage Provider.` |
| `https://staging-storage.babbage.systems` | `BRC-100 ttnNet Storage Provider.` |

</BlueTable>

The default for `test` is therefore a server that names teratestnet. For a testnet wallet, pass `storageUrl` with your own storage server, or keep the storage local with `Setup.createWalletSQLite`.

## Address format

One key gives a Mainnet address and a testnet address, and the first character tells them apart:

<BlueTable>

| Network | `toAddress` argument | Starts with |
| --- | --- | --- |
| Mainnet | `'mainnet'` or `'main'`, or no argument | `1` |
| testnet | `'testnet'` or `'test'` | `m` or `n` |
| teratestnet | `'testnet'` | `m` or `n` |

</BlueTable>

`toAddress` in `@bsv/sdk` throws `Invalid prefix` for `'ttn'`, `'teratestnet'`, `'stn'` and `'regtest'`. Teratestnet uses the testnet format, and its explorer API accepts an address that starts with `m` and rejects one that starts with `1`. An address shows only how it was encoded, not the network your code is on, as [How BSV networks differ](/concepts/networks/#how-to-tell-which-network-you-are-on) explains.
