Find the reference, guide or specification for each BSV service API. The services expose HTTP APIs, and <Hint tip="A WebSocket protocol on Socket.IO with BRC-103 mutual authentication">AuthSocket</Hint> uses WebSocket. For the hosts to call on each network, see [Network endpoints](/reference/networks/).

## HTTP APIs

<BlueTable>

| API | What it does | Reference | Guide or specification |
|---------|--------------|-----------|------------------------|
| ARC | Submits one transaction or a batch to <Hint tip="The broadcaster that came before BSV Broadcaster. BSV Broadcaster keeps most of its request and response shapes, but the ARC class of @bsv/sdk does not work with it">ARC</Hint> and reports the status of a transaction by its ID | [ARC broadcast](/reference/arc/) | [Broadcast with BSV Broadcaster](/guides/services/broadcasting/) |
| Overlay | Accepts <Hint tip="Background Evaluation Extended Format (BRC-62): a transaction with the evidence a host needs to verify it.">BEEF</Hint> transactions into an <Hint tip="Built from topic managers, which decide what is admitted, and lookup services, which query what was admitted.">overlay service</Hint>, answers lookup queries, lists the topic managers and lookup services it hosts, and exposes admin routes | [Overlay](/reference/overlay/) | [Run an overlay with @bsv/overlay-express](/sdk/packages/overlay-express/) |
| MessageBox | Holds messages for a named box on a <Hint tip="A store-and-forward messaging service: it holds each message until its recipient reads it">MessageBox</Hint> server until the recipient lists and acknowledges them, and registers devices and permissions | [MessageBox](/reference/message-box/) | [Send messages with @bsv/message-box-client](/sdk/packages/message-box-client/) |
| Merkle service | Watches transaction IDs and sends each <Hint tip="BSV Unified Merkle Path (BRC-74): a compact proof that a transaction is in a block">BUMP</Hint> to a callback URL when the proof is available | [Merkle service](/reference/merkle-service/) | [Merkle service specification](https://bsv-blockchain.github.io/ts-stack/specs/merkle-service/) |
| File storage | Uploads a file to a <Hint tip="Universal Hash Resolution Protocol (BRC-26): file storage where a file is found by the hash of its content">UHRP</Hint> storage server, finds who hosts a hash, lists uploads and renews an advertisement | [UHRP storage](/reference/uhrp/) | [UHRP specification](https://bsv-blockchain.github.io/ts-stack/specs/uhrp/) |
| Wallet storage | Exposes a remote wallet storage provider over HTTP: actions, outputs, certificates and sync | [Wallet storage](/reference/wallet-storage/) | [Plug in your own storage](/wallet-dev/wallet-toolbox/storage-adapter/) |
| BRC-121 payments | Charges for an HTTP resource. The resource answers `402 Payment Required` with the `x-bsv-sats` and `x-bsv-server` headers, and the client repeats the request with a payment | [BRC-121 payments](/reference/brc-121/) | [Gate an API behind payments](/guides/payments/) |

</BlueTable>

## Protocols

[ts-stack](https://bsv-blockchain.github.io/ts-stack/) describes these protocols as AsyncAPI specifications:

<CardGroup cols={2}>
  <Card title="AuthSocket WebSocket protocol" href="/reference/http-apis/authsocket/">
    Socket.IO with <Hint tip="Mutual authentication, where the wallet and the server prove their identity keys to each other">BRC-103</Hint> authentication, where each side signs its messages and the other verifies them.
  </Card>
  <Card title="BRC-103 mutual authentication" href="/reference/http-apis/brc-103-mutual-auth/">
    The handshake in which a client and a server prove their identity keys to each other, used by MessageBox and AuthSocket.
  </Card>
</CardGroup>

BRC-29 and GASP have no page on this site. Their specifications are in ts-stack:

- [BRC-29](https://bsv-blockchain.github.io/ts-stack/specs/brc-29-peer-payment/) covers peer-to-peer payments with a payment address derived from both identity keys.
- <Hint tip="Graph Aware Sync Protocol, how two overlay nodes synchronize transaction state">GASP</Hint> syncs transaction state between two overlay nodes, as described in its [specification](https://bsv-blockchain.github.io/ts-stack/specs/gasp-sync/).
