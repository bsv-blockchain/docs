Look up the exact methods, endpoints and errors your app works with on BSV, from the <Hint tip="BSV Request for Comments 100, the standard interface between apps and wallets">BRC-100</Hint> Wallet API to the HTTP APIs of BSV services. Use a reference page when you already know what your app calls and need the precise request, response, URL or error. To see how the parts fit together, read [How BSV works](/learn/). To build a feature step by step, follow the [guides](/guides/). The classes and methods of the TypeScript SDK packages are in the [SDK API reference](/sdk/api/).

## What each reference covers

Each row names a reference and what you look up in it. The Wallet API and the service APIs are generated from their OpenAPI specifications, with a page for each endpoint:

<BlueTable>

| Kind | What you look up | Reference |
| --- | --- | --- |
| Networks | The explorer, faucet, broadcast endpoints, wallet storage and address format of each network | [Network endpoints](/reference/networks/) |
| Errors | The cause of a wallet error, by its name or the start of its message, and what to check | [Error codes](/reference/errors/) |
| Wallet | Each wallet method, such as `createAction`, `listOutputs` and `getNetwork`, with its request and response | [Wallet API (BRC-100)](/reference/wallet-api/) |
| Service API | Submitting transactions to <Hint tip="The broadcast API that came before BSV Broadcaster">ARC</Hint>, one at a time or in a batch, and reading their status | [ARC broadcast](/reference/arc/) |
| Service API | Submitting tagged <Hint tip="Background Evaluation Extended Format (BRC-62), a transaction sent with its proofs">BEEF</Hint> transactions to an <Hint tip="Built from topic managers, which decide what is admitted, and lookup services, which query what was admitted.">overlay service</Hint>, querying its lookup services and managing it through its admin routes | [Overlay](/reference/overlay/) |
| Service API | Sending, listing and acknowledging messages in a <Hint tip="Holds each message until its recipient reads it">MessageBox</Hint>, and setting who may send to it | [MessageBox](/reference/message-box/) |
| Service API | Registering a transaction ID to receive its <Hint tip="The proof that a transaction is in a block, checked against the block header">Merkle proof</Hint> at a callback URL | [Merkle service](/reference/merkle-service/) |
| Service API | Uploading, finding and renewing files that a <Hint tip="Universal Hash Resolution Protocol (BRC-26), storage that addresses a file by its SHA-256 hash">UHRP</Hint> host serves | [UHRP storage](/reference/uhrp/) |
| Service API | The HTTP interface of a remote wallet storage provider: actions, outputs, certificates and sync | [Wallet storage](/reference/wallet-storage/) |
| Service API | The `402 Payment Required` exchange and the `x-bsv-*` headers of a paid request | [BRC-121 payments](/reference/brc-121/) |
| Standard | Resolving a <Hint tip="A handle that looks like an email address and names a user's services">Paymail</Hint> handle into a user's identity key | [Paymail](/standards/paymail/) |

</BlueTable>

The Bitcoin protocol and the Network Access Rules have their own sites, at [protocol.bsvblockchain.org](https://protocol.bsvblockchain.org/) and [nar.bsvblockchain.org](https://nar.bsvblockchain.org/).
