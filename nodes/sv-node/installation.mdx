Install SV Node, the BSV blockchain node software, so you can run `bitcoind` on testnet or Mainnet. The GitHub releases publish source only, so you download the Linux binary from the BSV download server, run the official Docker image, or build the release yourself. Most applications do not need their own node. If you only send and receive payments, use a wallet or a broadcast service instead, and install SV Node when you operate a miner or need direct node access. This page was written against SV Node 1.2.3, release tag `v1.2.3`.

<Callout type="info">
Start on testnet. Pass `-testnet` to `bitcoind` until you have confirmed your setup, and never point a test setup at Mainnet funds.
</Callout>

## Choose how to install

The three routes install the same release, 1.2.3 at the time of writing. Pick the one that fits your host, then follow its steps below.

<SvNodeInstallRoutes />

<Visibility for="agents">
Three routes install the same release, 1.2.3. Linux binary: the release as published, Linux on x86_64 only with no Windows binary, a checksum to verify the download, and `bitcoind` runs straight from the archive. Docker image: a container from the official image, pinned by tag, which generates a `bitcoin.conf`, keeps data in `/data` and is the route for hosts without a Linux binary. Build from source: a build you control, for a custom build, needing GCC 10.2 or later and the build dependencies.
</Visibility>

There is no Windows binary for 1.2.3, so on Windows run the Docker image.

## Install the software

Follow the steps for the route you chose.

### Download the Linux binary

The release tarball is on the [BSV download server](https://download.bitcoinsv.io/bitcoinsv/1.2.3/), next to a signed list of checksums.

<Steps>
<Step title="Download and verify the release">
Download the tarball and compute its hash:

```bash
curl -O https://download.bitcoinsv.io/bitcoinsv/1.2.3/bitcoin-sv-1.2.3-x86_64-linux-gnu.tar.gz
sha256sum bitcoin-sv-1.2.3-x86_64-linux-gnu.tar.gz
```

The output must be this line:

```text
13f222f5b466fe4af2bb867628354e4ae9711a10019e89fc7bf018b90e30b3c8  bitcoin-sv-1.2.3-x86_64-linux-gnu.tar.gz
```

The same hash is in the signed `SHA256SUMS.asc` next to the tarball on the server. It is a clear-signed PGP file, so you can check the signature with `gpg --verify SHA256SUMS.asc` once you hold the publisher's public key.
</Step>
<Step title="Unpack and start on testnet">
In the folder that holds the tarball, unpack it and start `bitcoind` on testnet. The archive holds `bitcoind`, `bitcoin-cli` and `bitcoin-tx` in `bin/`:

```bash
tar xzf bitcoin-sv-1.2.3-x86_64-linux-gnu.tar.gz
bitcoin-sv-1.2.3/bin/bitcoind -testnet -excessiveblocksize=10GB -maxstackmemoryusageconsensus=100MB -minminingtxfee=0.00000001
```

SV Node 1.2.3 refuses to start unless these three parameters are set, and exits with "Mandatory consensus parameter is not set" otherwise. [Configure SV Node](/nodes/sv-node/configuration/) explains them.

To confirm the release, run `bitcoind --version` from the unpacked folder:

```bash
bitcoin-sv-1.2.3/bin/bitcoind --version | head -1
```

```text
Bitcoin SV version v1.2.3
```
</Step>
</Steps>

### Run the Docker image

The image `bitcoinsv/bitcoin-sv` on Docker Hub provides `bitcoind`, `bitcoin-cli` and `bitcoin-tx`. It has a tag per release, for example `1.2.3`, plus `latest`.

<Steps>
<Step title="Start the node on testnet">
Pin the release tag so an upgrade is your decision:

```bash
docker run -d --name bitcoind-testnet bitcoinsv/bitcoin-sv:1.2.3 bitcoind -testnet -minminingtxfee=0.00000001
```

SV Node 1.2.3 refuses to start unless `minminingtxfee` is set. Without it the container exits with "Mandatory policy parameter is not set". The value above is the one used for testnet in the SV Node configuration examples. The image sets the two consensus parameters in the `bitcoin.conf` it generates.

Confirm the node is running and syncing. `bitcoin-cli` inside the container reads its credentials from the generated file, so point it there with `-conf`:

```bash
docker ps --filter name=bitcoind-testnet --format '{{.Names}} {{.Status}}'
docker exec bitcoind-testnet bitcoin-cli -conf=/data/bitcoin.conf -testnet getblockcount
```

```text
bitcoind-testnet Up 40 seconds
3419
```

The second line is the number of blocks the node has synced so far, so yours differs and grows while the node catches up. Without `-conf`, `bitcoin-cli` fails with "Could not locate RPC credentials". `docker logs bitcoind-testnet` shows the node connecting to peers and the new best block of each sync step.
</Step>
<Step title="Keep the blockchain data">
A container is ephemeral, so without a volume the node starts from an empty chain every time. The image keeps its data and a generated `bitcoin.conf` in `/data`, so remove the container from the previous step and start it again with a volume mounted there:

```bash
docker rm -f bitcoind-testnet
docker run -d --name bitcoind-testnet -v bitcoin-data:/data bitcoinsv/bitcoin-sv:1.2.3 bitcoind -testnet -minminingtxfee=0.00000001
```

After that you can remove the container and run the same command again, and the node continues from the data in the volume.
</Step>
</Steps>

### Build from source

The build instructions live in the repository for each release. The steps below follow `doc/build-unix.md` at [v1.2.3](https://github.com/bitcoin-sv/bitcoin-sv/blob/v1.2.3/doc/build-unix.md), the file to read at the tag you install.

<Steps>
<Step title="Check the toolchain and dependencies">
The build needs GCC 10.2 or later (C++20), plus the libssl, libboost and libevent development packages. The repository lists optional dependencies such as ZMQ and Berkeley DB, and the package commands for Debian, Ubuntu and CentOS.
</Step>
<Step title="Get the source">
Clone the release tag:

```bash
git clone --depth 1 --branch v1.2.3 https://github.com/bitcoin-sv/bitcoin-sv.git
cd bitcoin-sv
```
</Step>
<Step title="Build">
From the source root:

```bash
./autogen.sh
./configure
make
```

`make` puts `bitcoind` and `bitcoin-cli` in `src/`. Installing the binaries with `make install` is optional.
</Step>
<Step title="Start on testnet">
Start the built `bitcoind` with the same three required parameters as the binary route:

```bash
src/bitcoind -testnet -excessiveblocksize=10GB -maxstackmemoryusageconsensus=100MB -minminingtxfee=0.00000001
```

A build from the release tag reports its version as `v1.2.3-dev`.
</Step>
</Steps>

To skip installing the toolchain, the `bitcoinsv/bitcoin-sv-src` images on Docker Hub ship the dependencies and the node source for Debian, Ubuntu and CentOS.
