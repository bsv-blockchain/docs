Install SV Node, the BSV node software, so you can run `bitcoind` on testnet or Mainnet. The GitHub releases publish source only, so you download the Linux binary from the BSV download server, run the official Docker image, or build the release yourself. Most applications do not need their own node. If you only send and receive payments, use a wallet or a broadcast service instead, and install SV Node when you operate a miner or need direct node access.

<Callout type="info">
Start on testnet. Pass `-testnet` to `bitcoind` until you have confirmed your setup, and never point a test setup at Mainnet funds.
</Callout>

## Choose how to install

The three routes install the same release, 1.2.3 at the time of writing. Pick the one that fits your host, then follow its steps below.

There is no Windows binary for 1.2.3, so on Windows run the Docker image.

## Install the software

Follow the steps for the route you chose.

### Download the Linux binary

The release tarball is on the [BSV download server](https://download.bitcoinsv.io/bitcoinsv/1.2.3/), next to a signed list of checksums.

<Steps>
<Step title="Download and verify the release">
Download the tarball and compute its hash:

```bash
curl -O https://download.bitcoinsv.io/bitcoinsv/1.2.3/bitcoin-sv-1.2.3-x86_64-linux-gnu.tar.gz
sha256sum bitcoin-sv-1.2.3-x86_64-linux-gnu.tar.gz
```

The hash must be `13f222f5b466fe4af2bb867628354e4ae9711a10019e89fc7bf018b90e30b3c8`. Compare it with the signed `SHA256SUMS.asc` on the same server.
</Step>
<Step title="Unpack and start on testnet">
In the folder that holds the tarball, unpack it and start `bitcoind` on testnet. The archive holds `bitcoind`, `bitcoin-cli` and `bitcoin-tx` in `bin/`:

```bash
tar xzf bitcoin-sv-1.2.3-x86_64-linux-gnu.tar.gz
bitcoin-sv-1.2.3/bin/bitcoind -testnet -excessiveblocksize=10GB -maxstackmemoryusageconsensus=100MB -minminingtxfee=0.00000001
```

SV Node 1.2.3 refuses to start unless these three parameters are set, and exits with "Mandatory consensus parameter is not set" otherwise. [Configure SV Node](/nodes/sv-node/configuration) explains them.
</Step>
</Steps>

### Run the Docker image

The image `bitcoinsv/bitcoin-sv` on Docker Hub provides `bitcoind`, `bitcoin-cli` and `bitcoin-tx`. It has a tag per release, for example `1.2.3`, plus `latest`.

<Steps>
<Step title="Start the node on testnet">
Pin the release tag so an upgrade is your decision:

```bash
docker run -d --name bitcoind-testnet bitcoinsv/bitcoin-sv:1.2.3 bitcoind -testnet -minminingtxfee=0.00000001
```

SV Node 1.2.3 refuses to start unless `minminingtxfee` is set. Without it the container exits with "Mandatory policy parameter is not set". The value above is the one used for testnet in the SV Node configuration examples. The image sets the two consensus parameters in the `bitcoin.conf` it generates.
</Step>
<Step title="Keep the blockchain data">
A container is ephemeral, so without a volume the node starts from an empty chain every time. The image keeps its data and a generated `bitcoin.conf` in `/data`, so remove the container from the previous step and start it again with a volume mounted there:

```bash
docker rm -f bitcoind-testnet
docker run -d --name bitcoind-testnet -v bitcoin-data:/data bitcoinsv/bitcoin-sv:1.2.3 bitcoind -testnet -minminingtxfee=0.00000001
```

After that you can remove the container and run the same command again, and the node continues from the data in the volume.
</Step>
</Steps>

### Build from source

The build instructions live in the repository for each release. Read `doc/build-unix.md` at the tag you install, for example [v1.2.3](https://github.com/bitcoin-sv/bitcoin-sv/blob/v1.2.3/doc/build-unix.md).

<Steps>
<Step title="Check the toolchain and dependencies">
The build needs GCC 10.2 or later (C++20), plus the libssl, libboost and libevent development packages. The repository lists optional dependencies such as ZMQ and Berkeley DB, and the package commands for Debian, Ubuntu and CentOS.
</Step>
<Step title="Build">
Run these from the source root of the release you checked out:

```bash
./autogen.sh
./configure
make
```

Installing the binaries with `make install` is optional.
</Step>
</Steps>

To skip installing the toolchain, the `bitcoinsv/bitcoin-sv-src` images on Docker Hub ship the dependencies and the node source for Debian, Ubuntu and CentOS.
