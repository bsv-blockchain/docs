Send your first BSV payment from code, using BSV Desktop on testnet. In this tutorial, you:

- Set up a BSV Desktop wallet on testnet and fund it with free coins.
- Connect an app to the wallet with the TypeScript SDK.
- Send 1,000 testnet satoshis and see the payment on the testnet explorer.

The example runs on its own and needs no existing project.

## Before you begin

Make sure you have Node.js 22 or newer installed.

## How it works

Your app never holds a private key. In this tutorial, the scripts `connect.mjs` and `pay.mjs` play the role of your app. They run in a terminal and use `WalletClient` from `@bsv/sdk` to send requests to BSV Desktop, which shows each request and signs only after you approve. In a web app, the same calls go in the front-end code. Two sites complete the flow. A faucet sends the free testnet coins, and the testnet explorer shows the payment.

## Get free testnet coins

Your new wallet is empty. Take these steps to get free testnet coins from the BSV faucet:

<Steps>
  <Step title="Sign in to the faucet">
    Open [bsvfaucet.com](https://bsvfaucet.com/), click **Get testnet BSV**, and sign in with **Continue with BSV wallet**. If the browser asks to access other apps and services on this device, allow it, so the faucet can find your wallet.

    <Frame>
      <img src="/images/quick-start/07-faucet-sign-in.png" alt="The Sign in to BSV Faucet screen with the Continue with BSV wallet option" />
    </Frame>

    BSV Desktop shows a **Protocol Access Request** from `bsvfaucet.com` for the **bsv faucet login** protocol. Click **Grant Access**.

    <Frame>
      <img src="/images/quick-start/08-faucet-grant-access.png" alt="The Protocol Access Request window of BSV Desktop for bsvfaucet.com with the Deny and Grant Access buttons" />
    </Frame>
  </Step>
  <Step title="Request testnet coins">
    On the faucet page, paste your address in **Destination address**, enter an amount such as `1000000`, and click **Request BSV**.

    The amount is in satoshis, not BSV. A satoshi is the smallest unit of BSV, and 100,000,000 satoshis make 1 BSV, so `1` requests a single satoshi.

      <img src="/images/quick-start/09-faucet-request.png" alt="The BSV Testnet Faucet form with the Destination address and Amount fields and the Request BSV button" />

## Connect your app to the wallet

With the testnet wallet set up, create the project of your app in a terminal and connect it to the wallet:

<Steps>
  <Step title="Install the SDK">
    In the terminal, create a project in an empty folder and install the SDK:

    ```bash
    npm init -y
    npm install @bsv/sdk
    ```
  </Step>
  <Step title="Write the connection script">
    In the same folder, create a file named `connect.mjs`. This script is the part of your app that finds the wallet and reads from it:

    ```javascript connect.mjs
    import { WalletClient } from '@bsv/sdk'

    const wallet = new WalletClient('auto', 'example.com')

    const { publicKey } = await wallet.getPublicKey({ identityKey: true })
    console.log('Identity key:', publicKey)

    const { network } = await wallet.getNetwork()
    console.log('Network:', network)
    ```

    Two parts of the script are worth knowing:

    - `new WalletClient('auto', 'example.com')` finds the wallet available on your machine. The second value, `example.com`, is the name of your app. The wallet shows it whenever your app asks for something, such as a payment approval, and scripts run with Node.js must include it.
    - `getPublicKey({ identityKey: true })` asks the wallet for its identity key, the public key that identifies the wallet. The private key stays in the wallet.
  </Step>
  <Step title="Run the script">
    With BSV Desktop open and unlocked, run the script:

    ```bash
    node connect.mjs
    ```

    The output looks like this, with your own key:

    ```text
    Identity key: <66 character public key>
    Network: testnet
    ```
  </Step>
</Steps>

Your app is now connected to the wallet and can read from it on testnet. These calls only read from the wallet, so they cost nothing and BSV Desktop does not ask you to approve them.

## Send your first payment

Take these steps to send 1,000 satoshis to your own testnet address and see the payment on the testnet explorer. The coins come back to your wallet, so only the fee is spent:

<Steps>
  <Step title="Copy your current address">
    In BSV Desktop, click **Get paid** on the **Wallet** page and copy the address with **Copy address**. Copy it again here, even if you copied one in the first section.
  </Step>
  <Step title="Write the payment script">
    In the same folder as `connect.mjs`, create a file named `pay.mjs`. This script is the part of your app that asks the wallet for a payment:

    ```javascript pay.mjs
    import { P2PKH, WalletClient } from '@bsv/sdk'

    const wallet = new WalletClient('auto', 'example.com')

    const address = 'YOUR_TESTNET_ADDRESS'
    const lockingScript = new P2PKH().lock(address).toHex()

    const { txid } = await wallet.createAction({
      description: 'Pay my own address',
      outputs: [{
        satoshis: 1000,
        lockingScript,
        outputDescription: 'payment to my address'
      }]
    })

    console.log('Transaction ID:', txid)
    console.log('Explorer:', `https://test.whatsonchain.com/tx/${txid}`)
    ```

    <Callout type="warning">
      Replace `YOUR_TESTNET_ADDRESS` with the address you copied. Check it before you run the script, since a sent transaction cannot be reversed.
    </Callout>

    Two parts of the script do the work:

    - `new P2PKH().lock(address)` builds the <Hint tip="The part of a transaction output that sets the condition to spend it">locking script</Hint> of the payment, which sends the coins to your address. <Hint tip="Pay to Public Key Hash">P2PKH</Hint> is the standard way to lock coins to an address.
    - `createAction` asks the wallet to create the payment. The wallet chooses the coins, adds the fee, and signs, so the script never touches a private key.
  </Step>
  <Step title="Run the script and approve the payment">
    Run the script:

    ```bash
    node pay.mjs
    ```

    The script waits with no output until you approve the payment in BSV Desktop. The app opens a **Spending Request** window on top of its main screen, with the app name, `example.com`, the payment description, and the total with the fee. If you do not see it, switch to the BSV Desktop window, since it can stay behind the terminal. Click **Authorize**.

    <Frame>
      <img src="/images/quick-start/12-spending-request.png" alt="The Spending Request window of BSV Desktop from example.com for a payment named Pay my own address, with the total in satoshis and the Deny and Authorize buttons" />
    </Frame>

    After you approve, the script prints the transaction ID and a link to the testnet explorer, a site that shows the details of the transaction:

    ```text
    Transaction ID: <64 character transaction ID>
    Explorer: https://test.whatsonchain.com/tx/<64 character transaction ID>
    ```
  </Step>
  <Step title="Verify the payment on the testnet explorer">
    Open the explorer link from the output. The page shows your transaction on the BSV testnet. If the explorer shows **This page cannot be found**, it has not listed the payment yet, so wait a minute and reload.

    <Frame>
      <img src="/images/quick-start/13-explorer-transaction.png" alt="A transaction page on the WhatsOnChain testnet explorer with the Unconfirmed status, the fee offered to the miner and the size" />
    </Frame>
  </Step>
  <Step title="Add the payment back to your balance">
    The 1,000 satoshis went to your own address, so your **Available balance** first goes down by the amount plus the fee. To add the amount back, click **Get paid** on the **Wallet** page, then **Check for payments**. BSV Desktop shows **Received 1 address payment.**

    <Frame>
      <img src="/images/quick-start/14-payment-received.png" alt="The Payments screen of BSV Desktop with a Received 1 address payment notice" />
    </Frame>

    Your **Available balance** is now lower than before the payment only by the fee.

    <Frame>
      <img src="/images/quick-start/15-final-balance.png" alt="The Wallet page of BSV Desktop with the Available balance after the payment and the Pay my own address entry in Recent activity" />
    </Frame>
  </Step>
</Steps>

You have sent a first BSV payment from code, approved it in your wallet, and verified it on the testnet. In your own app, the same `WalletClient` calls stay in your code, and each user approves the payments in their own wallet, as you did in BSV Desktop.

## Troubleshooting

<AccordionGroup>
  <Accordion title={<>The script fails with "No wallet available over any communication substrate"</>}>
    This message means the script cannot reach BSV Desktop, usually because the app is closed or locked. Open BSV Desktop, unlock it with your device password, and run the script again.
  </Accordion>
  <Accordion title="The script prints nothing and does not finish">
    The script is waiting for you to approve the payment, so switch to the BSV Desktop window and answer the **Spending Request** that is open there.
  </Accordion>
  <Accordion title={<>The faucet shows "Couldn't verify wallet"</>}>
    Another wallet installed as a browser extension can answer the faucet before BSV Desktop. Turn off that extension while you sign in, keep BSV Desktop open and unlocked, and click **Continue with BSV wallet** again.
  </Accordion>
  <Accordion title={<>A payment fails with "HTTP status 400"</>}>
    This error means BSV Desktop did not complete the payment, either because you clicked **Deny** or because your balance does not cover the amount plus the fee. Check your balance in BSV Desktop, then run the script again and click **Authorize**.
  </Accordion>
</AccordionGroup>
