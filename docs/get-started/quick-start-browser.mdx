Send your first **BSV** payment from code, using BSV Desktop on testnet. In this tutorial, you:

- Set up a BSV Desktop wallet on testnet and fund it with free coins.
- Connect an app to the wallet with the TypeScript SDK.
- Send 1,000 testnet satoshis and see the payment on the testnet explorer.

The example runs on its own and needs no existing project.

## Before you begin

Make sure you have Node.js 22 or newer installed.

## How it works

Your app never holds a private key. In this tutorial, the scripts `connect.mjs` and `pay.mjs` play the role of your app. They run in a terminal and use `WalletClient` from `@bsv/sdk` to send requests to BSV Desktop, which shows each request and signs only after you approve. In a web app, the same calls go in the front-end code. Two sites complete the flow: a faucet sends the free testnet coins, and the testnet explorer shows the payment.

## Set up a testnet wallet

The first step is to set up [BSV Desktop](https://desktop.bsvb.tech/) on testnet:

<Steps>
  <Step title="Install BSV Desktop">
    Download the installer for your system, run it, and open the app.
  </Step>
  <Step title="Trust the local certificate">
    When the app opens for the first time, the **SSL Certificate Trust** dialog asks to add a certificate to your system. Click **Trust Certificate** and confirm the system prompt, or click **Not Now**. Either choice works for the scripts in this tutorial.
  </Step>
  <Step title="Switch the network to Testnet">
    Click **Create Wallet**, then the gear icon at the top right. In **Configuration**, which opens on **Mainnet**, select **Testnet** under **BSV Network** and click **Apply Configuration**. Leave the other options as they are. The network cannot be changed later in **Settings**, so check it before you continue.

    <Frame>
      <img src="/images/quick-start/01-configuration-testnet.png" alt="The Configuration screen of BSV Desktop with Testnet selected under BSV Network" />
    </Frame>
  </Step>
  <Step title="Create the wallet">
    Click **Create New Key**. The **Primary Key** field shows the recovery phrase of your wallet. Write it down, keep it somewhere safe, and click **Login**.

    <Callout type="warning">
      The recovery phrase restores your wallet, so keep it private. Never share it or paste it into code.
    </Callout>
  </Step>
  <Step title="Protect the wallet">
    Next, **Protect your wallet** asks for a passphrase. Enter it in both fields and click **Create vault**. The app asks for this passphrase each time it opens.
  </Step>
  <Step title="Copy your testnet address">
    The wallet opens on the **Legacy Bridge** page. Copy the address under **Your Payment Address**. A testnet address starts with `m` or `n`. The page shows a **Deprecated** notice about payments sent to an address, but these payments still work for funding a new wallet.

    <Frame>
      <img src="/images/quick-start/02-legacy-bridge-address.png" alt="The Legacy Bridge page of BSV Desktop showing a testnet payment address and its QR code" />
    </Frame>
  </Step>
  <Step title="Sign in to the faucet">
    Open [bsvfaucet.com](https://bsvfaucet.com/) and sign in with **Continue with BSV wallet**. If the browser asks to access other apps and services on this device, allow it, so the faucet can find your wallet.

    <Frame>
      <img src="/images/quick-start/03-faucet-sign-in.png" alt="The Sign in to BSV Faucet screen with the Continue with BSV wallet option" />
    </Frame>
  </Step>
  <Step title="Request testnet coins">
    On the faucet page, paste your address in **Destination address**, enter an amount such as `1000000`, and click **Request BSV**.

    The amount is in satoshis, not BSV. A satoshi is the smallest unit of BSV, and 100,000,000 satoshis make 1 BSV, so `1` requests a single satoshi.

    <Frame>
      <img src="/images/quick-start/04-faucet-request-success.png" alt="The BSV Testnet Faucet form after a request, with the Successfully sent message and the transaction ID" />
    </Frame>
  </Step>
</Steps>

<Callout type="info">
  The faucet allows up to 10,000,000 satoshis per request and one request every 24 hours.
</Callout>

The faucet confirms with a **Successfully sent** message and a transaction ID. BSV Desktop then imports the payment on its own and adds the coins to your balance within a few minutes. The **Available Balance** on the **Legacy Bridge** page may keep showing 0 satoshis, so check the amount under **Your Balance** at the top of the page.

<Frame>
  <img src="/images/quick-start/05-wallet-balance.png" alt="BSV Desktop after the faucet payment, with the new amount under Your Balance, 0 satoshis as the Available Balance on the Legacy Bridge page, and the payment under Received" />
</Frame>

## Connect your app to the wallet

With the testnet wallet set up, create the project of your app in a terminal and connect it to the wallet:

<Steps>
  <Step title="Install the SDK">
    In the terminal, create a project in an empty folder and install the SDK:

    ```bash
    npm init -y
    npm install @bsv/sdk
    ```
  </Step>
  <Step title="Write the connection script">
    In the same folder, create a file named `connect.mjs`. This script is the part of your app that finds the wallet and reads from it:

    ```javascript connect.mjs
    import { WalletClient } from '@bsv/sdk'

    const wallet = new WalletClient('auto', 'example.com')

    const { publicKey } = await wallet.getPublicKey({ identityKey: true })
    console.log('Identity key:', publicKey)

    const { network } = await wallet.getNetwork()
    console.log('Network:', network)
    ```

    Two parts of the script are worth knowing:

    - `new WalletClient('auto', 'example.com')` finds the wallet available on your machine. The second value, `example.com`, is the name of your app. The wallet shows it whenever your app asks for something, such as a payment approval, and scripts run with Node must include it.
    - `getPublicKey({ identityKey: true })` asks the wallet for its identity key, the public key that identifies the wallet. The private key stays in the wallet.
  </Step>
  <Step title="Run the script">
    With BSV Desktop open and unlocked, run the script:

    ```bash
    node connect.mjs
    ```

    The output looks like this, with your own key:

    ```text
    Identity key: <66 character public key>
    Network: testnet
    ```
  </Step>
</Steps>

Your app is now connected to the wallet and can read from it on testnet. These calls only read from the wallet, so they cost nothing and BSV Desktop does not ask you to approve them.

## Send your first payment

Take these steps to send 1,000 satoshis to your own testnet address and verify the payment on the testnet explorer. This example uses testnet, but keep in mind that a BSV transaction, on testnet or mainnet, cannot be reversed once broadcast. Always double check the recipient address and amount before sending.

<Steps>
  <Step title="Copy your current address">
    In BSV Desktop, open **Legacy Bridge** and copy the address under **Your Payment Address**. The address changes every day, so copy today's, even if you copied one in the first section.
  </Step>
  <Step title="Write the payment script">
    In the same folder as `connect.mjs`, create a file named `pay.mjs`. This script is the part of your app that asks the wallet for a payment. Replace `YOUR_TESTNET_ADDRESS` with the address you copied:

    ```javascript pay.mjs
    import { P2PKH, WalletClient } from '@bsv/sdk'

    const wallet = new WalletClient('auto', 'example.com')

    const address = 'YOUR_TESTNET_ADDRESS'
    const lockingScript = new P2PKH().lock(address).toHex()

    const { txid } = await wallet.createAction({
      description: 'Pay my own address',
      outputs: [{
        satoshis: 1000,
        lockingScript,
        outputDescription: 'payment to my address'
      }]
    })

    console.log('Transaction ID:', txid)
    console.log('Explorer:', `https://test.whatsonchain.com/tx/${txid}`)
    ```

    Two parts of the script do the work:

    - `new P2PKH().lock(address)` builds the part of the payment that sends the coins to your address.
    - `createAction` asks the wallet to create the payment. The wallet chooses the coins, adds the fee, and signs, so the script never touches a private key.
  </Step>
  <Step title="Run the script and approve the payment">
    Run the script:

    ```bash
    node pay.mjs
    ```

    The script waits with no output until you approve the payment in BSV Desktop. The app opens a **Spending Request** window on top of its main screen, with the app name, `example.com`, the payment description, and the total with the fee. If you do not see it, switch to the BSV Desktop window, since it can stay behind the terminal. Click **Authorize**.

    <Frame>
      <img src="/images/quick-start/06-spending-request.png" alt="The Spending Request window of BSV Desktop for a payment named Pay my own address, with the Deny and Authorize buttons" />
    </Frame>

    After you approve, the script prints the transaction ID and a link to the testnet explorer, a site that shows the details of the transaction:

    ```text
    Transaction ID: <64 character transaction ID>
    Explorer: https://test.whatsonchain.com/tx/<64 character transaction ID>
    ```
  </Step>
  <Step title="Verify the payment on the testnet explorer">
    Open the explorer link from the output. The page shows your transaction on the BSV testnet. If it does not show yet, wait a few minutes and reload.

    <Frame>
      <img src="/images/quick-start/07-explorer-transaction.png" alt="A transaction page on the WhatsOnChain testnet explorer with the block, the fee paid and the number of confirmations" />
    </Frame>
  </Step>
</Steps>

<Callout type="note">
  Use the link the script prints. Transaction links inside BSV Desktop open the mainnet explorer, which does not show testnet transactions.
</Callout>

BSV Desktop then detects the payment to your own address and imports it within a few minutes, so your balance goes down only by the fee. You have sent a first BSV payment from code, approved it in your wallet, and verified it on the testnet. In your own app, keep the same `WalletClient` calls in your code, and each user approves the payments in their own wallet, as you did in BSV Desktop.

## Troubleshooting

<AccordionGroup>
  <Accordion title={<>The script fails with "No wallet available over any communication substrate"</>}>
    This message means the script cannot reach BSV Desktop, usually because the app is closed or locked. Open BSV Desktop, unlock it with your passphrase, and run the script again.
  </Accordion>
  <Accordion title="The script prints nothing and does not finish">
    The script is waiting for you to approve the payment, so switch to the BSV Desktop window and answer the **Spending Request** that is open there.
  </Accordion>
  <Accordion title={<>A payment fails with "HTTP status 400"</>}>
    This error means BSV Desktop did not complete the payment, either because you clicked **Deny** or because your balance does not cover the amount plus the fee. Check your balance in BSV Desktop, then run the script again and click **Authorize**.
  </Accordion>
</AccordionGroup>
