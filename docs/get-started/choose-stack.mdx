<Callout type="warning">
Some code examples on this page use Mainnet (`network: 'main'`), moving real BSV. A BSV transaction cannot be reversed once broadcast. Review every example carefully and switch to a testnet setup while you're learning.
</Callout>

The right starting package depends on two things: who controls the private key, and how close to the raw protocol you need to work. Answer those and the rest follows.

<Callout type="info">
If you're building a server or agent wallet, or a wallet product, plan for key recovery and wallet records from the start, not as an afterthought. See ts-stack's [wallet backup and recovery guide](https://bsv-blockchain.github.io/ts-stack/guides/wallet-backup-recovery/) and [agent implementation brief](https://bsv-blockchain.github.io/ts-stack/guides/wallet-recovery-agent-brief/).
</Callout>

## Find Your Starting Point

<CardGroup cols={2}>
  <Card title="Browser app, user's wallet" icon="globe">
    Your app runs in the browser and the person using it already has their own wallet.
    → `@bsv/simple/browser`
  </Card>
  <Card title="Backend service, its own key" icon="server">
    A service or agent that holds and manages its own private key.
    → `@bsv/simple/server`
  </Card>
  <Card title="Coming from another chain" icon="right-left">
    You want to build transactions explicitly, the way you're used to elsewhere.
    → `@bsv/wallet-helper`
  </Card>
  <Card title="Building a wallet" icon="vault">
    You're implementing a wallet product or wallet infrastructure, not an app.
    → `@bsv/wallet-toolbox` + the BRC-100 spec
  </Card>
  <Card title="Working at the protocol level" icon="code">
    You need direct access to crypto, scripts, transactions, BEEF, or conformance testing.
    → `@bsv/sdk`
  </Card>
</CardGroup>

## Browser App

Use this when the person using your app already has a local <Hint tip="The standard wallet-to-application interface">BRC-100</Hint> wallet installed, such as BSV Desktop or BSV Browser.

```bash
npm install @bsv/simple
```

```typescript
import { createWallet } from '@bsv/simple/browser'

const wallet = await createWallet()
const recipientIdentityKey = '025706528f0f6894b2ba505007267ccff1133e004452a1f6b72ac716f246216366'
const result = await wallet.pay({
  to: recipientIdentityKey,
  satoshis: 1000
})

console.log(result.txid)
```

Your web app never holds a private key here. `createWallet()` finds whatever wallet is available on the user's machine and forwards BRC-100 calls to it.

## Transaction Builder

Reach for `@bsv/wallet-helper` when you want to construct transactions explicitly, outputs, scripts, metadata, inputs, change, without dropping all the way down to raw `WalletClient.createAction` and `signAction` calls.

This is usually the most comfortable starting point if you're coming from another blockchain stack: you still think in terms of transaction structure, while the user's BRC-100 wallet keeps control of keys and signing.

```bash
npm install @bsv/wallet-helper
```

## Server Agent

Use this when a service, bot, or test harness owns its own key, with no human wallet in the loop.

```bash
npm install @bsv/simple
```

```typescript
import { ServerWallet } from '@bsv/simple/server'

const wallet = await ServerWallet.create({
  privateKey: process.env.SERVER_PRIVATE_KEY!,
  network: 'main',
  storageUrl: 'https://store-us-1.bsvb.tech'
})
```

Keep `SERVER_PRIVATE_KEY` in a secret manager, never in code or plain config. If you run your own deployment, point `storageUrl` at your own region-specific Wallet Infra endpoint instead.

<Callout type="warning">
Our own testing found this funding path blocked on testnet: the documented `fund-metanet` tool fails, and the funding transaction is rejected for an invalid AtomicBEEF on both storage servers we tested. Flag this to the reader rather than presenting it as working end to end.
</Callout>

## Wallet Builder

Use `@bsv/wallet-toolbox` when you're building a BRC-100 wallet yourself: implementing storage, permission UX, or porting the wallet model to another language.

```bash
npm install @bsv/wallet-toolbox
```

It ships the reference pieces you'd otherwise have to build from scratch: `Wallet`, `WalletStorageManager`, storage providers, `WalletSigner`, `Services`, `Monitor`, key managers, permissions, and test utilities like `MockChain`.

## Protocol Engineer

Use `@bsv/sdk` directly when you need the primitives themselves, with nothing abstracted away above them.

```bash
npm install @bsv/sdk
```

It covers secp256k1/r1 cryptography, hashing, Script, transactions, <Hint tip="BRC-62">BEEF</Hint>, <Hint tip="BRC-74">BUMP</Hint>/Merkle paths, BRC-42 key derivation, ARC broadcasting, Chaintracks clients, the BRC-100 interface types, and wallet substrates.

## Service Operator

Some things aren't packages you install, they're shared infrastructure you run or connect to instead:

| Service | First page |
| --- | --- |
| Wallet state and UTXO storage | [Wallet Infra](https://bsv-blockchain.github.io/ts-stack/infrastructure/wallet-infra/) |
| Store-and-forward encrypted messages | [Message Box Server](https://bsv-blockchain.github.io/ts-stack/infrastructure/message-box-server/) |
| Shared on-chain topic lookup | [Overlay Server](https://bsv-blockchain.github.io/ts-stack/infrastructure/overlay-server/) |
| Content-addressed files | [UHRP servers](https://bsv-blockchain.github.io/ts-stack/infrastructure/uhrp-server-basic/) |
| Wallet authentication backend | [WAB](https://bsv-blockchain.github.io/ts-stack/infrastructure/wab/) |
| Block headers and Merkle roots | [Chaintracks Server](https://bsv-blockchain.github.io/ts-stack/infrastructure/chaintracks-server/) |

## Still Not Sure? Match It to What You're Building

| What you're building | Start with | Usually adds |
| --- | --- | --- |
| Browser app | `@bsv/simple/browser` | `@bsv/message-box-client`, overlays |
| Transaction-building app | `@bsv/wallet-helper` | `@bsv/templates`, BRC-100 method reference |
| Server agent | `@bsv/simple/server` | `@bsv/402-pay`, Message Box |
| BRC-100 wallet | `@bsv/wallet-toolbox` | Wallet Infra, WAB, Chaintracks |
| Protocol library | `@bsv/sdk` | Conformance vectors |
| Overlay node | `@bsv/overlay`, `@bsv/overlay-express` | `@bsv/overlay-topics`, GASP |
| Token system | `@bsv/btms`, `@bsv/btms-permission-module` | Overlay topics, wallet permissions |
| Authenticated API | `@bsv/auth-express-middleware` | BRC-100 wallet |
| Payment-gated API | `@bsv/402-pay` | `@bsv/payment-express-middleware` |
| File storage | `@bsv/overlay-topics` | UHRP server |
