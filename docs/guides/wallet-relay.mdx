Add a login to your web app that works with the wallet the user has. If BSV Desktop runs on the same computer, the app connects to it directly. If not, the app shows a QR code, and the user logs in with a wallet on their phone, such as BSV Browser. At the end, a React (Vite) app and a small Express backend log the user in either way and show the identity key of their wallet. Use this when your users might not have a desktop wallet installed.

## Before you begin

You need Node.js 22.18 or newer, which runs TypeScript files directly, and a React project built with Vite and written in TypeScript. To try the desktop path, open BSV Desktop on testnet. [Send a payment from a web app](/docs/get-started/quick-start-browser/) shows how to set it up. This guide was tested with `@bsv/wallet-relay` 0.7.0, `@bsv/sdk` 3.2.1, Express 5 and Vite 8.

## How it works

<Hint tip="An encrypted connection between a web app and a phone wallet, through a relay server that cannot read the messages">Wallet Relay</Hint> is the feature of the `@bsv/wallet-relay` package that pairs a web page with a phone wallet. The login tries the computer first and falls back to the phone:

| Path | When it is used | How the app reaches the wallet |
|---|---|---|
| Desktop | A <Hint tip="BSV Request for Comments 100, the standard interface between apps and wallets">BRC-100</Hint> wallet such as BSV Desktop runs on the computer | `WalletClient` from `@bsv/sdk`, on the user's machine |
| Wallet Relay | No wallet is found on the computer, and the user chooses to log in with the phone | Your backend creates a session and a QR code. The user scans it, approves the connection on the phone, and the page sends wallet calls through your backend to the phone |

Both paths give your app an object with the same wallet methods, so the rest of your code does not change. The phone keeps the keys, and the messages between the page and the phone are encrypted, so the relay only passes them on.

The relay carries 16 wallet methods: `getPublicKey`, `listOutputs`, `createAction`, `signAction`, `createSignature`, `verifySignature`, `listActions`, `internalizeAction`, `acquireCertificate`, `relinquishCertificate`, `listCertificates`, `revealCounterpartyKeyLinkage`, `createHmac`, `verifyHmac`, `encrypt` and `decrypt`. `getNetwork` is not one of them, so a phone wallet cannot tell your app which network it is on.

## Add the backend

The backend creates the pairing sessions and runs the relay. Run these steps in a new `backend` folder next to your React project:

<Steps>
  <Step title="Install the packages">
    Install the packages and set the folder to use ES modules:

    ```bash
    npm install @bsv/wallet-relay @bsv/sdk express ws qrcode
    npm install --save-dev @types/express @types/node
    npm pkg set type=module
    ```
  </Step>
  <Step title="Create the relay key">
    <Callout type="warning">
      The relay key is a private key. Keep it in `.env` and never commit it. It does not hold funds, but anyone who has it can act as your backend in a pairing.
    </Callout>

    The phone checks the identity key of your backend, which is in the QR code, so the backend must keep the same key across restarts. Add a key to `.env`. The command skips this if `.env` already has one, so running it again never replaces the key:

    ```bash
    grep -q WALLET_PRIVATE_KEY .env 2>/dev/null || node --input-type=commonjs -e "const {PrivateKey}=require('@bsv/sdk'); console.log('WALLET_PRIVATE_KEY=' + PrivateKey.fromRandom().toHex())" >> .env
    echo .env >> .gitignore
    ```
  </Step>
  <Step title="Write the server">
    Create `server.ts`. `WalletRelayService` adds the session routes under `/api` and the relay at `/ws` to your Express app:

    ```ts server.ts
    import { createServer } from 'node:http'
    import express from 'express'
    import { PrivateKey, ProtoWallet } from '@bsv/sdk'
    import { WalletRelayService } from '@bsv/wallet-relay'

    const app = express()
    app.use(express.json({ limit: '64kb' }))
    const server = createServer(app)

    const wallet = new ProtoWallet(PrivateKey.fromHex(process.env.WALLET_PRIVATE_KEY!))
    new WalletRelayService({ app, server, wallet })

    server.listen(3000, () => console.log('Wallet Relay backend on http://localhost:3000'))
    ```

    `ProtoWallet` only encrypts and signs the relay messages, and it never sees the user's wallet.
  </Step>
  <Step title="Start the server">
    Start the server from the `backend` folder:

    ```bash
    node --env-file=.env server.ts
    ```

    The server prints its address:

    ```text
    Wallet Relay backend on http://localhost:3000
    ```
  </Step>
</Steps>

## Add the login to your app

The login component tries the desktop wallet, then offers the phone. Run these steps in your React project:

<Steps>
  <Step title="Install the packages">
    Install the packages in your React project:

    ```bash
    npm install @bsv/wallet-relay @bsv/sdk
    ```
  </Step>
  <Step title="Send the API calls to the backend">
    In `vite.config.ts`, forward `/api` and the relay at `/ws` to the backend, so the page and the backend share one origin:

    ```ts vite.config.ts
    import { defineConfig } from 'vite'
    import react from '@vitejs/plugin-react'

    export default defineConfig({
      plugins: [react()],
      server: {
        proxy: {
          '/api': 'http://localhost:3000',
          '/ws': { target: 'ws://localhost:3000', ws: true }
        }
      }
    })
    ```
  </Step>
  <Step title="Create the login component">
    Create `src/Login.tsx`:

    ```tsx src/Login.tsx
    import { useEffect, useState } from 'react'
    import type { WalletClient, WalletInterface } from '@bsv/sdk'
    import type { WalletMethodName } from '@bsv/wallet-relay/client'
    import { QRDisplay, WalletConnectionModal, useWalletRelayClient } from '@bsv/wallet-relay/react'

    export type AppWallet = Pick<WalletInterface, WalletMethodName>

    type LoginProps = {
      onLogin: (wallet: AppWallet, identityKey: string) => void
    }

    export function Login({ onLogin }: LoginProps) {
      const [showQR, setShowQR] = useState(false)
      const [loginError, setLoginError] = useState('')
      const { session, wallet, error, createSession } = useWalletRelayClient({ autoCreate: false })

      function showPhoneLogin() {
        setShowQR(true)
        void createSession()
      }

      async function loginWithLocalWallet(local: WalletClient) {
        try {
          const { publicKey } = await local.getPublicKey({ identityKey: true })
          onLogin(local, publicKey)
        } catch (e) {
          setLoginError(`BSV Desktop did not log you in: ${String(e)}`)
          showPhoneLogin()
        }
      }

      useEffect(() => {
        if (session?.status !== 'connected' || !wallet) return
        wallet
          .getPublicKey({ identityKey: true })
          .then(({ publicKey }) => onLogin(wallet, publicKey))
          .catch(e => setLoginError(`The phone did not log you in: ${String(e)}`))
      }, [session?.status, wallet, onLogin])

      if (showQR) {
        return (
          <div>
            {(loginError || error) && <p>{loginError || error}</p>}
            <QRDisplay session={session} onRefresh={createSession} />
          </div>
        )
      }

      return (
        <WalletConnectionModal
          onLocalWallet={local => void loginWithLocalWallet(local)}
          onMobileQR={showPhoneLogin}
          mobileLabel="Log in with your phone"
        />
      )
    }
    ```

    `WalletConnectionModal` looks for a wallet on the computer when it loads. If it finds one, it calls `onLocalWallet` and shows nothing. If not, it shows an **Install BSV Wallet** link to BSV Desktop and the **Log in with your phone** button. `autoCreate: false` creates a backend session only when the user selects that button. When the phone approves, `wallet` stops being `null` and forwards each call to the phone. The identity key of the wallet is the user's ID in both paths. If BSV Desktop is found but refuses the identity key, for example because it is locked, the login shows the error and offers the phone instead.
  </Step>
  <Step title="Show the login">
    Render the login in `src/App.tsx` until the user is logged in:

    ```tsx src/App.tsx
    import { useState } from 'react'
    import { Login, type AppWallet } from './Login'

    export default function App() {
      const [user, setUser] = useState<{ wallet: AppWallet; identityKey: string } | null>(null)

      if (!user) return <Login onLogin={(wallet, identityKey) => setUser({ wallet, identityKey })} />

      return <p>Logged in as {user.identityKey}</p>
    }
    ```

    Keep `user.wallet` for the rest of your app. It has the same methods whether it is BSV Desktop or the phone.
  </Step>
  <Step title="Try the desktop path">
    Start the app with `npm run dev` and open `http://localhost:5173`. With BSV Desktop open and unlocked, the page shows the identity key of the wallet, shortened here:

    ```text
    Logged in as 023f…b5ab
    ```
  </Step>
</Steps>

## Log in with a phone

A phone wallet connects only to an app served over HTTPS, so the phone path needs a public address. Point an HTTPS development tunnel at port 5173, add its domain to `server.allowedHosts` in `vite.config.ts`, and add two lines to the `.env` of the backend, below `WALLET_PRIVATE_KEY`:

```text
RELAY_URL=wss://YOUR_DOMAIN
ORIGIN=https://YOUR_DOMAIN
```

Replace `YOUR_DOMAIN` with the domain of the tunnel. `ORIGIN` is the address that the QR code points the phone to, and the phone adds `/ws` to `RELAY_URL` to reach the relay through the Vite proxy. Restart the backend after you change them.

Then log in from the phone:

<Steps>
  <Step title="Put BSV Browser on testnet">
    In BSV Browser, open **Wallet**, **Settings**, **BSV Network** and choose **Testnet**. The relay does not carry `getNetwork`, so your app cannot check which network the phone wallet is on. Check it yourself before you log in.
  </Step>
  <Step title="Open the phone login">
    Close BSV Desktop, open the app at `https://YOUR_DOMAIN` and select **Log in with your phone**.

    <Frame>
      <img src="/images/wallet-relay/02-log-in-with-phone.png" alt="The login page with an Install BSV Wallet link and the Log in with your phone button highlighted" />
    </Frame>
  </Step>
  <Step title="Scan the QR code">
    The page shows a QR code and `Waiting for mobile...`. Scan the code with the camera of the phone.

    <Frame>
      <img src="/images/wallet-relay/03-scan-qr-code.png" alt="The login page showing a blurred QR code highlighted, with the status Waiting for mobile" />
    </Frame>
  </Step>
  <Step title="Approve the connection">
    BSV Browser opens on **Connect Wallet** and shows the address of your app under **Origin**. Check it, then select **Approve**. The page shows the identity key of the phone wallet.
  </Step>
</Steps>

<Callout type="note">
  The QR code is a short-lived invitation, and the first wallet to scan it pairs with the page. Do not show it in a screen share or save it in a log.
</Callout>

## Troubleshooting

<AccordionGroup>
  <Accordion title="Server fails with Cannot use import statement outside a module">
    The `backend` folder is not set to ES modules. Run `npm pkg set type=module` in it and start the server again.
  </Accordion>
  <Accordion title="Phone rejects the QR code">
    BSV Browser connects only to an app served over HTTPS. Check that `ORIGIN` starts with `https://` and `RELAY_URL` with `wss://`, and that you opened the app at that address.
  </Accordion>
</AccordionGroup>
