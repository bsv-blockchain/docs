Build the login of your app around the wallet the user already has: a wallet on the same computer, such as BSV Desktop, or a wallet on their phone, such as BSV Browser, paired by QR code. At the end, a React (Vite) app with a small Express backend looks for a wallet when the user selects **Log in**, waits while that wallet is locked, offers the phone when there is none, and shows which wallet is connected with a way to change it. Use this for any app where users log in with a wallet instead of a password.

<Callout type="note">
  <Hint tip="BSV Request for Comments 185, Wallet Substrate Discovery, Selection, and Encrypted Mobile Connections">BRC-185</Hint> is a [proposed specification](https://brc.bsvb.net/brc/185) for how apps find, choose and connect to wallets, including phone wallets. It is a draft, last revised in October 2026, and no wallet or package implements all of it yet. This guide uses the packages available today and follows the login behavior of BRC-185 where they allow it. [Gaps with BRC-185](#gaps-with-brc-185) lists what they cannot do yet.
</Callout>

## Before you begin

You need Node.js 22.18 or newer, which runs TypeScript files directly, and a React project built with Vite and written in TypeScript. To try the computer path, open BSV Desktop on testnet. [Send a payment from a web app](/docs/get-started/quick-start-browser/) shows how to set it up. This guide was tested with `@bsv/wallet-relay` 0.7.0, `@bsv/sdk` 3.2.1, Express 5 and Vite 8.

## How the login decides

The login reacts to what it finds, in the order BRC-185 sets out:

| Situation | What the login does |
|---|---|
| The user selects **Log in** | Looks for a <Hint tip="BSV Request for Comments 100, the standard interface between apps and wallets">BRC-100</Hint> wallet on this computer. It does not look before the user asks |
| A wallet answers and is unlocked | Logs in with it |
| A wallet answers and is locked | Waits, and asks the user to unlock it or approve the request. A locked wallet is not a missing one, so the login does not offer to install a wallet or switch to another one by itself. The user can still choose the phone |
| No wallet answers | Says that no wallet was found on this computer, and offers the phone, another look and a link to install BSV Desktop |
| The user chooses the phone | Shows a QR code. The user scans it with the phone and approves the connection there |
| The user is logged in | Shows which wallet is connected, with a control to change wallet or log out |

The identity key that the wallet returns tells the page who the user is. It does not prove it to your server: the page reads the key in the browser, and nothing checks that the caller holds the private key behind it, so any script or modified client can send any public key. To have your API know which user sent each request, add mutual authentication as in [Authenticate users with their wallet](/docs/guides/identity-auth/).

## How the phone connection works

<Hint tip="An encrypted connection between a web app and a phone wallet, through a relay that cannot read the messages">Wallet Relay</Hint> is the `@bsv/wallet-relay` package that pairs a web page with a phone wallet. Your backend creates a pairing session and a QR code. The phone scans the code, reads the session from your app over HTTPS, and exchanges encrypted messages with your backend through the relay. The page sends each wallet call to your backend, which passes it to the phone. The phone keeps the keys.

<Callout type="warning">
  Your backend encrypts and decrypts the messages, so it can read every wallet call and result that goes to the phone. Only the relay in between sees nothing but encrypted messages. BRC-185 calls this backend mode and asks the app and the wallet to tell the user before they approve. BSV Browser 1.8.1 does not show that notice, so say it in your app, for example in your privacy notice.
</Callout>

The relay carries 16 wallet methods: `getPublicKey`, `listOutputs`, `createAction`, `signAction`, `createSignature`, `verifySignature`, `listActions`, `internalizeAction`, `acquireCertificate`, `relinquishCertificate`, `listCertificates`, `revealCounterpartyKeyLinkage`, `createHmac`, `verifyHmac`, `encrypt` and `decrypt`. `getNetwork` is not one of them, so a phone wallet cannot tell your app which network it is on.

## Add the backend

The backend creates the pairing sessions and runs the relay. Run these steps in a new `backend` folder next to your React project:

<Steps>
  <Step title="Install the packages">
    Install the packages and set the folder to use ES modules:

    ```bash
    npm install @bsv/wallet-relay @bsv/sdk express ws qrcode
    npm install --save-dev @types/express @types/node
    npm pkg set type=module
    ```
  </Step>
  <Step title="Create the relay key">
    <Callout type="warning">
      The relay key is a private key. Keep it in `.env` and never commit it. It does not hold funds, but anyone who has it can act as your backend in a pairing.
    </Callout>

    The phone checks the identity key of your backend, which is in the QR code, so the backend must keep the same key across restarts. Add a key to `.env`. The command skips this if `.env` already has one, so running it again never replaces the key:

    ```bash
    grep -q WALLET_PRIVATE_KEY .env 2>/dev/null || node --input-type=commonjs -e "const {PrivateKey}=require('@bsv/sdk'); console.log('WALLET_PRIVATE_KEY=' + PrivateKey.fromRandom().toHex())" >> .env
    echo .env >> .gitignore
    ```
  </Step>
  <Step title="Write the server">
    Create `server.ts`. `WalletRelayService` adds the session routes under `/api` and the relay at `/ws` to your Express app:

    ```ts server.ts
    import { createServer } from 'node:http'
    import express from 'express'
    import { PrivateKey, ProtoWallet } from '@bsv/sdk'
    import { WalletRelayService } from '@bsv/wallet-relay'

    const app = express()
    app.use(express.json({ limit: '64kb' }))
    const server = createServer(app)

    const wallet = new ProtoWallet(PrivateKey.fromHex(process.env.WALLET_PRIVATE_KEY!))
    new WalletRelayService({ app, server, wallet })

    server.listen(3000, () => console.log('Wallet Relay backend on http://localhost:3000'))
    ```

    `ProtoWallet` encrypts and decrypts the relay messages with the relay key. It is not the user's wallet and holds no funds.
  </Step>
  <Step title="Start the server">
    Start the server from the `backend` folder:

    ```bash
    node --env-file=.env server.ts
    ```

    The server prints its address:

    ```text
    Wallet Relay backend on http://localhost:3000
    ```
  </Step>
</Steps>

## Add the login to your app

The login component holds the decisions from the table above. Run these steps in your React project:

<Steps>
  <Step title="Install the packages">
    Install the packages in your React project:

    ```bash
    npm install @bsv/wallet-relay @bsv/sdk
    ```
  </Step>
  <Step title="Send the API calls to the backend">
    In `vite.config.ts`, forward `/api` and the relay at `/ws` to the backend, so the page and the backend share one origin:

    ```ts vite.config.ts
    import { defineConfig } from 'vite'
    import react from '@vitejs/plugin-react'

    export default defineConfig({
      plugins: [react()],
      server: {
        proxy: {
          '/api': 'http://localhost:3000',
          '/ws': { target: 'ws://localhost:3000', ws: true }
        }
      }
    })
    ```
  </Step>
  <Step title="Create the login component">
    Create `src/Login.tsx`:

    ```tsx src/Login.tsx
    import { useEffect, useRef, useState } from 'react'
    import { WalletClient, type WalletInterface } from '@bsv/sdk'
    import type { WalletMethodName } from '@bsv/wallet-relay/client'
    import { QRDisplay, useWalletRelayClient } from '@bsv/wallet-relay/react'

    export type AppWallet = Pick<WalletInterface, WalletMethodName>

    export type User = {
      wallet: AppWallet
      identityKey: string
      via: 'this computer' | 'your phone'
      logOut: () => void
    }

    type Status = 'start' | 'looking' | 'waiting' | 'none' | 'pairing'

    export function Login({ onLogin }: { onLogin: (user: User) => void }) {
      const [status, setStatus] = useState<Status>('start')
      const [message, setMessage] = useState('')
      const relay = useWalletRelayClient({ autoCreate: false })
      const attempt = useRef(0)

      async function findComputerWallet() {
        const thisAttempt = ++attempt.current
        const stillCurrent = () => attempt.current === thisAttempt
        setMessage('')
        setStatus('looking')
        const local = new WalletClient('auto')
        try {
          await local.connectToSubstrate()
        } catch {
          if (stillCurrent()) setStatus('none')
          return
        }
        if (!stillCurrent()) return
        setStatus('waiting')
        try {
          await local.waitForAuthentication()
          const { publicKey } = await local.getPublicKey({ identityKey: true })
          if (stillCurrent()) onLogin({ wallet: local, identityKey: publicKey, via: 'this computer', logOut: () => {} })
        } catch (e) {
          if (!stillCurrent()) return
          setMessage(`The wallet did not log you in: ${String(e)}`)
          setStatus('none')
        }
      }

      function startPhoneLogin() {
        attempt.current++
        setMessage('')
        setStatus('pairing')
        void relay.createSession()
      }

      function cancelPhoneLogin() {
        relay.cancelSession()
        setStatus('none')
      }

      useEffect(() => {
        if (relay.session?.status !== 'connected' || !relay.wallet) return
        const phone = relay.wallet
        phone
          .getPublicKey({ identityKey: true })
          .then(({ publicKey }) =>
            onLogin({ wallet: phone, identityKey: publicKey, via: 'your phone', logOut: relay.cancelSession })
          )
          .catch(e => setMessage(`Your phone did not log you in: ${String(e)}`))
      }, [relay.session?.status, relay.wallet, relay.cancelSession, onLogin])

      return (
        <div>
          {(message || relay.error) && <p>{message || relay.error}</p>}
          {status === 'start' && <button onClick={() => void findComputerWallet()}>Log in</button>}
          {status === 'looking' && <p>Looking for a wallet on this computer…</p>}
          {status === 'waiting' && (
            <>
              <p>Wallet found. Unlock it, or approve the request in the wallet.</p>
              <button onClick={startPhoneLogin}>Use your phone instead</button>
            </>
          )}
          {status === 'none' && (
            <>
              {!message && <p>No wallet found on this computer.</p>}
              <button onClick={startPhoneLogin}>Log in with your phone</button>
              <button onClick={() => void findComputerWallet()}>Look again</button>
              <a href="https://desktop.bsvb.tech" target="_blank" rel="noreferrer">Install BSV Desktop</a>
            </>
          )}
          {status === 'pairing' && (
            <>
              <p>Scan the code with your phone, or in BSV Browser open Connections and select Scan QR Code.</p>
              <QRDisplay session={relay.session} onRefresh={relay.createSession} />
              <button onClick={cancelPhoneLogin}>Cancel</button>
            </>
          )}
        </div>
      )
    }
    ```

    `connectToSubstrate` looks for a wallet on this computer and fails if none answers. `waitForAuthentication` then waits until the wallet is unlocked, which is the waiting state. If the user chooses the phone while the wallet is still locked, `attempt` makes the computer path stop, so unlocking the wallet later does not log the user in with it or take away the QR code. On the phone path, `autoCreate: false` creates a backend session only when the user chooses the phone, and `cancelSession` ends it and closes the connection to the phone. When the phone approves, `relay.wallet` stops being `null` and forwards each call to the phone.
  </Step>
  <Step title="Show the login">
    Replace `src/App.tsx` so it shows the login until the user is logged in, and then which wallet is connected:

    ```tsx src/App.tsx
    import { useState } from 'react'
    import { Login, type User } from './Login'

    export default function App() {
      const [user, setUser] = useState<User | null>(null)

      function logOut() {
        user?.logOut()
        setUser(null)
      }

      if (!user) return <Login onLogin={setUser} />

      return (
        <div>
          <p>Logged in with the wallet on {user.via} as {user.identityKey}</p>
          <button onClick={logOut}>Change wallet or log out</button>
        </div>
      )
    }
    ```

    Keep `user.wallet` for the rest of your app. It has the same methods whether the wallet is on the computer or the phone.

    <Callout type="warning">
      `user.identityKey` identifies the user inside the page only. Do not send it to your API as proof of who the user is, because a client can send another user's key. Before your server trusts a key for data or actions, verify it with mutual authentication, as in [Authenticate users with their wallet](/docs/guides/identity-auth/).
    </Callout>
  </Step>
  <Step title="Try the computer path">
    Start the app with `npm run dev`, open `http://localhost:5173` and select **Log in**. With BSV Desktop open and unlocked, the page shows the identity key of the wallet, shortened here:

    ```text
    Logged in with the wallet on this computer as 023f…b5ab
    ```
  </Step>
</Steps>

## Log in with a phone

A phone wallet connects only to an app served over HTTPS, so the phone path needs a public address. Point an HTTPS development tunnel at port 5173, add its domain to `server.allowedHosts` in `vite.config.ts`, and add two lines to the `.env` of the backend, below `WALLET_PRIVATE_KEY`:

```text
RELAY_URL=wss://YOUR_DOMAIN
ORIGIN=https://YOUR_DOMAIN
```

Replace `YOUR_DOMAIN` with the domain of the tunnel. `ORIGIN` is the address that the QR code points the phone to, and the phone adds `/ws` to `RELAY_URL` to reach the relay through the Vite proxy. Restart the backend after you change them.

Then log in from the phone:

<Steps>
  <Step title="Put BSV Browser on testnet">
    In BSV Browser, open **Wallet**, **Settings**, **BSV Network** and choose **Testnet**. The relay does not carry `getNetwork`, so your app cannot check which network the phone wallet is on. Check it yourself before you log in.
  </Step>
  <Step title="Open the phone login">
    Close BSV Desktop, open the app at `https://YOUR_DOMAIN`, select **Log in**, and then select **Log in with your phone**.

    <Frame>
      <img src="/images/wallet-login/02-log-in-with-phone.png" alt="The login page saying no wallet was found on this computer, with the Log in with your phone button highlighted next to Look again and Install BSV Desktop" />
    </Frame>
  </Step>
  <Step title="Scan the QR code">
    The page shows a QR code and `Waiting for mobile...`. Scan it with the camera of the phone. You can also scan it from inside BSV Browser: open the menu with the three dots at the bottom right, select the link icon next to **Wallet** to open **Connections**, and select **Scan QR Code**.

    <Frame>
      <img src="/images/wallet-login/03-scan-qr-code.png" alt="The login page showing a blurred QR code highlighted, the status Waiting for mobile and a Cancel button" />
    </Frame>
  </Step>
  <Step title="Approve the connection">
    BSV Browser opens on **Connect Wallet** and shows the address of your app under **Origin**. Check that it is the app you opened, then select **Approve**. The page shows the identity key of the phone wallet. The connection then appears in **Connections** in BSV Browser, where the user can disconnect it.
  </Step>
</Steps>

<Callout type="note">
  The QR code is a short-lived invitation, and the first wallet to scan it pairs with the page. Do not show it in a screen share or save it in a log.
</Callout>

## Gaps with BRC-185

Today's packages predate BRC-185, so this login cannot yet do everything the specification asks:

- **One wallet on the computer.** `WalletClient` tries a fixed set of local ports and uses the first wallet that answers. It cannot list several wallets on one computer or let the user choose between them
- **No wallet name or remembered choice.** The login cannot tell which wallet product answered, so it says "the wallet on this computer", and it looks again at every login
- **Blocked looks like absent.** If the browser blocks access to local ports, the login reports that no wallet was found. **Look again** lets the user retry after allowing access
- **No confirmation code.** BRC-185 has the app and the phone show the same code for the user to compare. With Wallet Relay the user checks the origin only
- **The backend reads the calls.** BRC-185 prefers pairing where only the page can decrypt. Wallet Relay decrypts on your backend, as the warning above explains
- **Part of the wallet interface.** The relay carries 16 methods. BRC-185 requires all 28 BRC-100 methods

## Troubleshooting

<AccordionGroup>
  <Accordion title="Server fails with Cannot use import statement outside a module">
    The `backend` folder is not set to ES modules. Run `npm pkg set type=module` in it and start the server again.
  </Accordion>
  <Accordion title="Phone rejects the QR code">
    BSV Browser connects only to an app served over HTTPS. Check that `ORIGIN` starts with `https://` and `RELAY_URL` with `wss://`, and that you opened the app at that address.
  </Accordion>
</AccordionGroup>
