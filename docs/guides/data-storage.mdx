title: Store data and files
description: Put data in a BSV transaction output through the user's wallet and read it back with the TypeScript SDK.
---

A **BSV** transaction can carry data next to the coins it moves. An output that starts with `OP_FALSE OP_RETURN` holds any bytes you choose. It cannot be spent, and anyone with the transaction id can read it. Your app writes the output through the user's wallet and reads it back from the same wallet.

## Before you begin

You need a funded testnet wallet in [BSV Desktop](https://desktop.bsvb.tech/). [Send a payment from a web app](/docs/get-started/quick-start-browser/) shows how to set one up.

<Callout type="note">
The network comes from the wallet, not from the code. These examples use a testnet wallet. To use mainnet, read [Move your app to mainnet](/docs/guides/go-to-mainnet/).
</Callout>

## Write data to a transaction output

Follow these steps to write a short text to a transaction output with the wallet in BSV Desktop:

<Steps>
  <Step title="Connect to the wallet">

    ```ts
    import { WalletClient } from '@bsv/sdk'

    const wallet = new WalletClient('auto', 'localhost')
    ```

    The second argument of `WalletClient` is the originator, the name BSV Desktop shows for your app. A Node script cannot reach the wallet without one.
  </Step>
  <Step title="Build the data output">

    ```ts
    import { LockingScript, OP, Utils } from '@bsv/sdk'

    const data = Utils.toArray('hello from my app', 'utf8')
    const pushOp = (n: number) =>
      n <= 75 ? n : n <= 0xff ? OP.OP_PUSHDATA1 : n <= 0xffff ? OP.OP_PUSHDATA2 : OP.OP_PUSHDATA4

    const lockingScript = new LockingScript([
      { op: OP.OP_FALSE },
      { op: OP.OP_RETURN },
      { op: pushOp(data.length), data }
    ])
    ```

    The SDK has no template for a data output, so the script is built from its two opcodes and one data push.
  </Step>
  <Step title="Create the transaction">

    ```ts
    const { txid } = await wallet.createAction({
      description: 'Store a note on-chain',
      outputs: [{
        lockingScript: lockingScript.toHex(),
        satoshis: 0,
        outputDescription: 'Stored note',
        basket: 'notes',
        tags: ['note']
      }],
      options: { acceptDelayedBroadcast: false }
    })
    ```

    The output holds no coins, so the cost is the network fee, which grows with the size of the transaction and uses the rate set in BSV Desktop under **Settings**, **Advanced settings**, **Transaction fees**. The `basket` and `tags` let you list the output later, and `acceptDelayedBroadcast: false` makes the wallet broadcast the transaction before the call returns.
  </Step>
  <Step title="Authorize the request in BSV Desktop">
    BSV Desktop opens a **Spending Request** with the name of your app, the `description` you passed and the network fee. The call returns after you click **Authorize**. The `description` and the `outputDescription` are what the user reads, so write them for the user.
  </Step>
</Steps>

<Callout type="info">
Anything in the output is public. Do not put personal data or secrets in it, and encrypt what should stay private before you write it.
</Callout>

## Read the data back

Once the transaction is broadcast, read the output from the wallet and from the network:

<Steps>
  <Step title="List the output from the wallet">

    ```ts
    const { outputs } = await wallet.listOutputs({
      basket: 'notes',
      tags: ['note'],
      include: 'locking scripts'
    })

    const readData = (hex: string): number[] => {
      const bytes = Utils.toArray(hex, 'hex')
      if (bytes[0] !== OP.OP_FALSE || bytes[1] !== OP.OP_RETURN) throw new Error('Not a data output')
      const reader = new Utils.Reader(bytes.slice(2))
      const op = reader.readUInt8()
      const length = op <= 75 ? op
        : op === OP.OP_PUSHDATA1 ? reader.readUInt8()
        : op === OP.OP_PUSHDATA2 ? reader.readUInt16LE()
        : reader.readUInt32LE()
      return reader.read(length)
    }

    for (const output of outputs) {
      console.log(Utils.toUTF8(readData(output.lockingScript!)))
    }
    ```

    The helper skips the two opcodes and the push length bytes, so it returns only your data.
  </Step>
  <Step title="Check the transaction on an explorer">
    Open the transaction in a testnet explorer such as [WhatsOnChain](https://test.whatsonchain.com/), by its `txid`. Output 0 has a value of 0 and the same script. An explorer can cut a large script short, and the WhatsOnChain API returns only its first 50,000 bytes.
  </Step>
</Steps>

## Store data with @bsv/simple

If your app already uses `@bsv/simple`, its wallet writes the same output in one call:

```ts
import { createWallet } from '@bsv/simple/browser'

const wallet = await createWallet()

const text = await wallet.inscribeText('hello from my app', { basket: 'notes' })
const json = await wallet.inscribeJSON({ note: 'hello' }, { basket: 'notes' })

console.log(text.txid, json.txid)
```

`createWallet` connects to BSV Desktop with its own originator, and BSV Desktop asks you to authorize each call, as it does for `createAction`. The output is the same `OP_FALSE OP_RETURN` script, so the helper above reads it when you list the `notes` basket without the `tags` filter.

## Troubleshooting

<AccordionGroup>
  <Accordion title="No wallet available over any communication substrate" defaultOpen>
    The script reached no wallet. A Node script cannot connect to BSV Desktop without an originator, so pass one as the second argument of `WalletClient`, for example `new WalletClient('auto', 'localhost')`, and keep BSV Desktop open and unlocked.
  </Accordion>
  <Accordion title="The call never returns">
    BSV Desktop is waiting for you to authorize the **Spending Request**. Bring the app to the front, check the amount and click **Authorize**.
  </Accordion>
</AccordionGroup>
