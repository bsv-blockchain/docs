Every BSV wallet has an identity key. With **mutual authentication**, your API and the caller's wallet prove to each other who they are before a request is served, so each route can read the identity key of the wallet that called it.

## Before you begin

To follow this guide, have these ready:

- Node.js 22 or newer.
- BSV Desktop with a testnet wallet, set up as in [Send a payment from a web app](/docs/get-started/quick-start-browser/).

## Set up the authenticated API

`@bsv/auth-express-middleware` protects the routes on the server, and `AuthFetch` from `@bsv/sdk` signs each request on the client.

### Protect the API with the auth middleware

Start with the server, which is the part that identifies the caller:

<Steps>
  <Step title="Install the packages">
    ```bash
    npm install @bsv/auth-express-middleware @bsv/sdk @bsv/wallet-toolbox express
    npm install --save-dev tsx typescript @types/express @types/node
    ```

    The middleware works with `@bsv/sdk` 2.8.5 or later in the 2.x line, and with 3.x. The code in this guide uses top-level `await`, so set `"type": "module"` in your `package.json`.
  </Step>
  <Step title="Create the server wallet">
    ```ts wallet.ts
    import { PrivateKey } from '@bsv/sdk'
    import { Setup } from '@bsv/wallet-toolbox'

    export async function createServerWallet(rootKeyHex = PrivateKey.fromRandom().toHex()) {
      const identityKey = PrivateKey.fromHex(rootKeyHex).toPublicKey().toString()
      const filePath = `server-${identityKey.slice(0, 8)}.sqlite`
      const env = {
        chain: 'test' as const,
        identityKey,
        identityKey2: identityKey,
        filePath,
        taalApiKey: '',
        devKeys: {},
        mySQLConnection: ''
      }
      const { wallet } = await Setup.createWalletSQLite({ env, rootKeyHex, filePath, databaseName: 'server' })
      return wallet
    }
    ```

    The middleware signs its responses with a wallet that implements `WalletInterface`, and a bare `ProtoWallet` does not qualify. The identity key of this wallet is the identity of your server.
  </Step>
  <Step title="Add the middleware">
    ```ts server.ts
    import express from 'express'
    import { createAuthMiddleware, type AuthRequest } from '@bsv/auth-express-middleware'
    import { createServerWallet } from './wallet.js'

    const wallet = await createServerWallet()
    const app = express()
    app.use(express.json())
    app.use(createAuthMiddleware({ wallet }))
    ```

    Authentication is required by default, so a request without the authentication headers gets a `401` response.
  </Step>
  <Step title="Read the caller in a route">
    ```ts server.ts
    app.get('/private', (req: AuthRequest, res) => {
      res.json({ identityKey: req.auth?.identityKey })
    })

    app.listen(3000)
    ```

    The value of `req.auth.identityKey` is the identity key of the wallet that signed the request. To also receive certificates the caller holds, the middleware accepts `certificatesToRequest` and `onCertificatesReceived`, described on the [package page on npm](https://www.npmjs.com/package/@bsv/auth-express-middleware).
  </Step>
</Steps>

### Call the API with AuthFetch

With the server running, call it from a client whose wallet is BSV Desktop:

<Steps>
  <Step title="Create the client">
    ```ts client.ts
    import { AuthFetch, WalletClient } from '@bsv/sdk'

    const wallet = new WalletClient('auto', 'localhost')
    const authFetch = new AuthFetch(wallet)

    const response = await authFetch.fetch('http://localhost:3000/private')
    console.log(await response.json())
    ```

    The second argument of `WalletClient` is the `originator`, a domain name that identifies your app to the wallet. A Node client has to pass one, or the connection to BSV Desktop fails. BSV Desktop shows the originator as the app name in its permission windows and keeps permissions per originator.
  </Step>
  <Step title="Run the server and the client">
    Run the server and the client in two terminals:

    ```bash
    npx tsx server.ts
    npx tsx client.ts
    ```

    The client prints the identity key of the BSV Desktop wallet that signed the request:

    ```text
    { identityKey: '<identity key of your wallet>' }
    ```

    BSV Desktop shows the start of this key for each profile under **Wallet profiles**.
  </Step>
</Steps>

The response also carries the identity key of the server in the `x-bsv-auth-identity-key` header, so the client can tell which server answered.

<Callout type="info">
  By default BSV Desktop answers these calls without asking. With **Require permission for signature creation**, **Require permission for public key revelation** and **Require permission for identity key revelation** turned on in **Settings**, and the app reloaded, the first call opens two **Protocol Access Request** windows, for **identity key retrieval** and **auth message signature**. Select **Grant Access** to let the call through, and BSV Desktop remembers the choice for the originator.
</Callout>

## Handle callers without authentication

To serve a route to everyone and still identify the callers who are authenticated, set `allowUnauthenticated`:

```ts server.ts
app.use(createAuthMiddleware({ wallet, allowUnauthenticated: true }))
```

A request from `AuthFetch` still reaches the route with the real identity key, and any other request arrives with the identity key `unknown`. Treat `unknown` as "not authenticated" and never as permission to do anything.

## Keep the server identity stable

To keep one server identity across restarts, create the key once and pass it to `createServerWallet`:

<Steps>
  <Step title="Generate the key">
    ```bash
    node -e "import('@bsv/sdk').then(({ PrivateKey }) => console.log(PrivateKey.fromRandom().toHex()))"
    ```

    Keep the key in a secret store, not in your repository, because anyone who holds it can run a server with your identity.
  </Step>
  <Step title="Pass the key to the wallet">
    ```ts server.ts
    const wallet = await createServerWallet(process.env.SERVER_ROOT_KEY)
    ```
  </Step>
</Steps>

Without a key, the server gets a new random one, and so a new identity, at every start. BSV Desktop stores its **auth message signature** permission per server identity key.

## Prepare the API for production

Before the API serves real users, check these points:

- Share the session state across instances. The default session manager lives in the memory of one process, so a service with several instances needs a shared `sessionManager`.
- Review `transportLimits`. The defaults are a 30 second request timeout, 1,000 pending requests per process and 8 MiB for a signed response, and a request over a limit is rejected with `413` or `503`. Do not set `maxPendingRequests` too low, because each authenticated request can hold more than one pending slot.
- Move off testnet by following [Go to mainnet](/docs/guides/go-to-mainnet/).

## Troubleshooting

<AccordionGroup>
  <Accordion title={<>A request returns <code>401</code> with "Mutual-authentication failed!"</>} defaultOpen>
    The request reached a protected route without the authentication headers, for example from `fetch`, `curl` or a browser. Call the route with `AuthFetch`, or set `allowUnauthenticated` on the middleware if the route must accept anonymous callers.
  </Accordion>
  <Accordion title="No wallet available over any communication substrate. Install a BSV wallet today!">
    `WalletClient` raises this error when it cannot reach a wallet. A Node client gets it when no `originator` is passed, even with BSV Desktop running. Pass an `originator`, as in `client.ts`.
  </Accordion>
  <Accordion title="Type 'ProtoWallet' is missing the following properties from type 'WalletInterface'">
    `createAuthMiddleware` and `AuthFetch` take a `WalletInterface`, and a `ProtoWallet` does not implement it. Pass a wallet like the one `createServerWallet` returns.
  </Accordion>
  <Accordion title={<>Top-level <code>await</code> is currently not supported with the "cjs" output format</>}>
    `tsx` runs the files as CommonJS. Set `"type": "module"` in your `package.json`.
  </Accordion>
</AccordionGroup>
