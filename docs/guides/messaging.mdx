---
title: "Send messages between users"
description: "Send encrypted messages and payments between users with MessageBox, which holds each message until its recipient reads it."
---

**MessageBox** delivers encrypted messages and payments from one user to another, addressed by identity key. A host keeps each message in the recipient's box until the recipient reads and acknowledges it, so the two users do not need to be online at the same time. The client encrypts the body with your wallet before it leaves your app, so the host only stores ciphertext.

## Before you begin

The examples are Node scripts that talk to [BSV Desktop](https://desktop.bsvb.tech/) on testnet. Set it up and fund it as in the [Quick Start](/docs/get-started/quick-start-browser/), since a few hundred satoshis cover everything on this page.

<Callout type="note">
The examples on this page run on testnet, with free coins. Before you switch them to mainnet, where every transaction costs real BSV and cannot be reversed, read [Move your app to mainnet](/docs/guides/go-to-mainnet/).
</Callout>

## Connect to your wallet

The first step is to install the packages and connect a client to BSV Desktop:

<Steps>
  <Step title="Install the packages">

    ```bash
    npm install @bsv/message-box-client @bsv/sdk
    ```

  </Step>
  <Step title="Create the clients">

    ```ts
    import { MessageBoxClient } from '@bsv/message-box-client'
    import { WalletClient } from '@bsv/sdk'

    const wallet = new WalletClient('auto', 'localhost')
    const client = new MessageBoxClient({
      walletClient: wallet,
      networkPreset: 'testnet'
    })
    ```

    The second argument of **`WalletClient`** is the originator, the name BSV Desktop shows for your app. A Node script cannot reach the wallet without one. The **`networkPreset`** tells the client which overlay network to ask for the recipient's MessageBox host. When it finds none, the client uses the host you configure, which defaults to **`https://message-box-us-1.bsvb.tech`**.

  </Step>
  <Step title="Get your identity key">

    ```ts
    const { publicKey: me } = await wallet.getPublicKey({ identityKey: true })
    ```

    Your identity key is the address other users send to, and you need theirs to send to them. To learn how it is derived, read [How keys and identity work](/docs/concepts/keys-identity/).

  </Step>
</Steps>

## Send a message

With the client ready, send a message to an identity key, starting with your own to try it:

<Steps>
  <Step title="Send the message">

    ```ts
    const sent = await client.sendMessage({
      recipient: me,
      messageBox: 'inbox',
      body: { text: 'Hello from MessageBox' }
    })
    console.log(sent) // { status: 'success', messageId: '...', message: '...' }
    ```

    The **`body`** is a string or an object. The **`messageBox`** is free text and belongs to the recipient, so each identity has its own **`inbox`**. A message to an ordinary box name costs nothing.

  </Step>
</Steps>

The host accepts a message for any valid key, so a successful send does not tell you that the recipient exists. It refuses messages over roughly 98,000 characters of text.

## Read and acknowledge messages

The recipient reads the box with their own wallet and acknowledges each message once the app has handled it:

<Steps>
  <Step title="List the messages">

    ```ts
    const messages = await client.listMessages({ messageBox: 'inbox' })
    for (const m of messages) {
      console.log(m.sender, m.body)
    }
    ```

    The client decrypts each body for you. A message has **`messageId`**, **`body`** and **`sender`**, which is the sender's identity key. The dates come back as **`createdAt`** and **`updatedAt`**, although the package types declare **`created_at`** and **`updated_at`**. A third identity that lists a box with the same name sees nothing of yours.

  </Step>
  <Step title="Acknowledge the messages">

    ```ts
    await client.acknowledgeMessage({
      messageIds: messages.map(m => m.messageId)
    })
    ```

    A message stays in the box until it is acknowledged.

  </Step>
</Steps>

After the acknowledgment the host deletes the messages, and a second acknowledgment of the same ids fails.

## Receive messages as they arrive

To get a message the moment it is sent, instead of listing the box, the recipient listens on a live connection and the sender sends over it:

<Steps>
  <Step title="Listen for messages">

    ```ts
    const live = new MessageBoxClient({
      walletClient: wallet,
      networkPreset: 'testnet',
      socketOptions: { managerOptions: { transports: ['websocket'] } }
    })

    await live.listenForLiveMessages({
      messageBox: 'inbox',
      onMessage: message => console.log(message.sender, message.body)
    })
    ```

    The default connection does not work with the default host and ends with "WebSocket authentication timed out!", so the **`transports`** option is required. Pass each client its own **`socketOptions`** object.

  </Step>
  <Step title="Send a live message">

    ```ts
    await sender.sendLiveMessage({
      recipient: recipientIdentityKey,
      messageBox: 'inbox',
      body: { text: 'Hello now' }
    })
    ```

    The **`sender`** is a client built like **`live`**, with the sender's wallet. It returns `{ status: 'success', messageId }`.

  </Step>
</Steps>

The listener receives **`sender`**, **`messageId`** and **`body`**, with the body as a JSON string. The message also stays in the box until the recipient acknowledges it.

## Send one message to several recipients

To deliver the same message to many identity keys in one call, send it as a batch:

<Steps>
  <Step title="Send the batch">

    ```ts
    const batch = await client.sendMessageToRecipients({
      recipients: [firstIdentityKey, secondIdentityKey],
      messageBox: 'inbox',
      body: { text: 'Hello everyone' },
      skipEncryption: true
    })
    console.log(batch.status, batch.sent.length, batch.blocked)
    ```

    A batch cannot be encrypted for each recipient, so the client requires **`skipEncryption: true`** and the host stores the body as readable text. Send one encrypted message per recipient when the content is private.

  </Step>
</Steps>

The result lists the delivered messages in **`sent`**. A recipient that blocked you appears in **`blocked`** while **`status`** stays `success`, and a batch holds up to 100 unique recipients.

## Control who can send to you

To stop a sender, set a permission on your box for that sender's identity key. A **`recipientFee`** of **`-1`** blocks them, and **`0`** allows them again:

<Steps>
  <Step title="Block a sender">

    ```ts
    await client.setMessageBoxPermission({
      messageBox: 'inbox',
      sender: senderIdentityKey,
      recipientFee: -1
    })
    ```

    The blocked sender's next **`sendMessage`** is refused with **`ERR_DELIVERY_BLOCKED`**, and nothing reaches your box.

  </Step>
</Steps>

## Send a payment between users

A payment travels as a message in the recipient's **`payment_inbox`** box on the same host, and the payment client builds the transaction with your wallet and sends it:

<Steps>
  <Step title="Send the payment">

    ```ts
    import { PeerPayClient } from '@bsv/message-box-client'

    const peerPay = new PeerPayClient({
      walletClient: wallet,
      originator: 'localhost'
    })

    await peerPay.sendPayment({ recipient: me, amount: 100 })
    ```

    BSV Desktop opens a **Spending Request** for the amount plus the network fee, and the call waits until you authorize it.

  </Step>
  <Step title="Accept the payment">

    ```ts
    const incoming = await peerPay.listIncomingPayments()
    await peerPay.acceptPayment(incoming[0])
    ```

    Each incoming payment has **`messageId`**, **`sender`** and a **`token`** with the **`amount`**. Accepting it adds the payment to the recipient's wallet and acknowledges the message.

  </Step>
</Steps>

The recipient needs a wallet that can internalize payments, such as BSV Desktop. A payment you send to yourself costs only the network fee. Instead of accepting a payment, **`rejectPayment(payment)`** returns it to the sender minus 1,000 satoshis.

## Troubleshooting

<AccordionGroup>
  <Accordion title={<>"Identity key retrieval failed"</>} defaultOpen>
    The client cannot reach BSV Desktop. A Node script needs an originator, as in **`new WalletClient('auto', 'localhost')`**, and BSV Desktop must be open and on testnet.
  </Accordion>
  <Accordion title={<>"Failed to acknowledge messages on all hosts:"</>}>
    The id is unknown, already acknowledged, or belongs to another identity. List the box again and acknowledge only the ids it returns.
  </Accordion>
  <Accordion title={<>"Failed to send message."</>}>
    The host refused the request, most likely because the message is too large. Keep each message under roughly 98,000 characters of text.
  </Accordion>
  <Accordion title={<>"Message recipient must be a canonical compressed public key."</>}>
    The recipient is not an identity key. Use the 66 character hex key that starts with **`02`** or **`03`**.
  </Accordion>
  <Accordion title={<>`ERR_MISSING_PAYMENT_TX`</>}>
    The box charges a fee and the message carried no payment. Ask what the box costs with **`getMessageBoxQuote`**, then send with **`checkPermissions: true`** and a **`maximumPayment`** at or above the quote.
  </Accordion>
  <Accordion title={<>`ERR_INTERNALIZE_FAILED`</>}>
    The box charges a delivery fee to the host, as the built-in `notifications` box does, and the host could not take the payment. The wallet has already paid, so the message is not delivered and the fee is spent. Check **`deliveryFee`** in the quote before sending, and use a box that has none while you build on testnet.
  </Accordion>
  <Accordion title={<>"BRC-29 settlement failed recipient, amount, transaction, or wallet validation."</>}>
    The recipient wallet cannot internalize the payment. Accept it with a wallet such as BSV Desktop.
  </Accordion>
  <Accordion title={<>"A shared multi-recipient batch cannot be encrypted per recipient."</>}>
    A batch is stored as readable text. Pass **`skipEncryption: true`** if that is acceptable, or send one encrypted message per recipient.
  </Accordion>
  <Accordion title={<>"WebSocket authentication timed out!"</>}>
    The default live connection does not work with the default host. Create the client with **`socketOptions: { managerOptions: { transports: ['websocket'] } }`**.
  </Accordion>
  <Accordion title={<>"managerOptions.hostname cannot override the authenticated server URL"</>}>
    Two clients share one **`socketOptions`** object. Pass each client a new object.
  </Accordion>
  <Accordion title={<>"BRC-29 settlement could not be built safely."</>}>
    The payment could not be built, often because the wallet holds less than the amount plus the fee. Check the balance in BSV Desktop.
  </Accordion>
  <Accordion title="The balance in BSV Desktop does not change after accepting a payment">
    The Wallet page does not update by itself. Press its refresh button.
  </Accordion>
</AccordionGroup>
