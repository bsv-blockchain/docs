Send a transaction that carries data to an overlay topic, then look it up back, so your app can find its own transactions without scanning the chain. An **overlay** indexes the transactions that matter to your app under a topic, and this guide builds that flow as a Node script with BSV Desktop on testnet that you can adapt to your own app.

## Before you begin

You need a funded testnet wallet in [BSV Desktop](https://desktop.bsvb.tech/) and Node.js 22 or newer. [Send a payment from a web app](/docs/get-started/quick-start-browser/) shows how to set up the wallet.

An overlay is shared infrastructure, so a transaction is tracked only by a host that runs your topic. There is no public overlay on testnet that runs every topic, so for development run an overlay yourself with [Run the overlay server](/docs/guides/services/stack-services/overlay-server/) or point at a host that runs your topic.

<Callout type="info">
The wallet decides the network. These examples use a testnet wallet and a local overlay. To use Mainnet, read [Move your app to Mainnet](/docs/guides/go-to-mainnet/).
</Callout>

## How it works

An <Hint tip="Built from topic managers, which decide what is admitted, and lookup services, which query what was admitted.">overlay service</Hint> pairs a topic with a lookup service. The topic is what a host stores, and the lookup service is how your app asks for it:

<OverlayFlow />

A topic name starts with `tm_`, and a lookup service name starts with `ls_`.

## Connect to your wallet

The first step is to install the SDK and connect a script to BSV Desktop.

<Steps>
  <Step title="Install the SDK">

    Use npm in your project folder:

    ```bash
    npm install @bsv/sdk
    ```

    This guide is written against `@bsv/sdk` 3.x.

  </Step>
  <Step title="Create the script">

    Create `overlay.mjs` and connect to the wallet:

    ```js overlay.mjs
    import { WalletClient } from '@bsv/sdk'

    const wallet = new WalletClient('auto', 'localhost')
    const networkPreset = 'local'
    ```

    The second argument of **`WalletClient`** is the originator, the name BSV Desktop shows for your app. A Node script cannot reach the wallet without it. The **`networkPreset`** is the network the overlay discovery uses: `mainnet`, `testnet`, or `local` for an overlay on `localhost`.

  </Step>
</Steps>

## Send a transaction to a topic

With the wallet connected, create an output that carries your data and broadcast it to the topic.

<Steps>
  <Step title="Build the output">

    Add a `PushDrop` with your data to the same file:

    ```js
    import { PushDrop, SecurityLevels, Utils } from '@bsv/sdk'

    const pushdrop = new PushDrop(wallet)
    const keyID = Date.now().toString()
    const lockingScript = await pushdrop.lock(
      [Utils.toArray('Hello overlay', 'utf8')],
      [SecurityLevels.Silent, 'my app'],
      keyID,
      'self'
    )
    ```

    The <Hint tip="The part of a transaction output that sets the condition to spend it.">locking script</Hint> from **`PushDrop`** stores one or more data fields, here a short message.

  </Step>
  <Step title="Create the transaction">

    Ask the wallet to create the action with the output, in the same file:

    ```js
    const action = await wallet.createAction({
      description: 'my app output',
      outputs: [
        {
          satoshis: 1,
          lockingScript: lockingScript.toHex(),
          basket: 'my app',
          outputDescription: 'my app output',
          customInstructions: keyID
        }
      ]
    })
    ```

    BSV Desktop opens a **Spending Request** window from the originator, `localhost`, showing the amount in satoshis and the action description, and you approve it with **Authorize**. The amount includes the transaction fee, so it is more than the 1 satoshi output. The **`basket`** keeps the output in your wallet under an app name, and **`customInstructions`** carries the key ID the output was created with.

  </Step>
  <Step title="Broadcast to the topic">

    Send the transaction to the topic with a topic broadcaster:

    ```js
    import { TopicBroadcaster, Transaction } from '@bsv/sdk'

    const tx = Transaction.fromAtomicBEEF(action.tx)
    const result = await tx.broadcast(
      new TopicBroadcaster(['tm_myapp'], { networkPreset })
    )
    console.log(result)
    ```

    The host answers with a <Hint tip="Submitted Transaction Execution AcKnowledgment: which outputs each topic admitted.">STEAK</Hint> for the topics it accepted. A success looks like this:

    ```text
    {
      "status": "success",
      "txid": "9a6f3dadf189198432a1b10f79f0cda69bed276a38a8f5d1a65f757dbf7f0a6f",
      "message": "Sent to 1 Overlay Services host."
    }
    ```

    The topic name must start with `tm_` and must be one the host runs. A transaction is permanent once it is mined, so a wrong output cannot be undone.

  </Step>
</Steps>

## Look up the transaction

Now that the host indexed the output, ask for it by lookup service and read the data back.

<Steps>
  <Step title="Query the lookup service">

    Query the service in the same file:

    ```js
    import { LookupResolver } from '@bsv/sdk'

    const resolver = new LookupResolver({ networkPreset })
    const answer = await resolver.query(
      { service: 'ls_myapp', query: { limit: 10, skip: 0 } },
      10000
    )
    console.log(JSON.stringify(answer))
    ```

    The name must start with `ls_`. The service answers with the outputs it admitted:

    ```json
    {
      "type": "output-list",
      "outputs": [{ "outputIndex": 1, "beef": [1, 1, 1, 1, 111, 0] }]
    }
    ```

  </Step>
  <Step title="Read the data back">

    Decode the <Hint tip="Background Evaluation Extended Format (BRC-62): a transaction with the evidence a host needs to verify it.">BEEF</Hint> in the same file to get the fields you stored:

    ```js
    import { PushDrop } from '@bsv/sdk'

    const output = answer.outputs[0]
    const txFromOverlay = Transaction.fromBEEF(Uint8Array.from(output.beef))
    const decoded = PushDrop.decode(txFromOverlay.outputs[output.outputIndex].lockingScript)
    const message = Buffer.from(decoded.fields[0]).toString('utf8')
    console.log(message)
    ```

    The decoded field is the message you wrote, `Hello overlay`, and the last field is the `PushDrop` signature.

  </Step>
</Steps>

## Troubleshooting

<AccordionGroup>
  <Accordion title="Lookup fails with no competent hosts">

    The resolver found no overlay host for the service, with a message such as `No competent testnet hosts found by the SLAP trackers for lookup service: ls_myapp`. The service name has no host behind it on that network. Run an overlay that has the service and set `networkPreset` to match where it runs.

  </Accordion>
  <Accordion title="Script cannot reach BSV Desktop">

    The script throws `No wallet available over any communication substrate. Install a BSV wallet today!` when the wallet client has no originator. Create it as `new WalletClient('auto', 'localhost')`, with `localhost` as the originator, and keep BSV Desktop open.

  </Accordion>
  <Accordion title="Host rejects the transaction">

    The topic manager returned no admitted outputs, so the broadcast answers `ERR_ALL_HOSTS_REJECTED` or `No host acknowledged the required topics.` The output does not match the topic format, or the topic is not one the host runs. Check that the topic name starts with `tm_` and that the host has it registered.

  </Accordion>
</AccordionGroup>
