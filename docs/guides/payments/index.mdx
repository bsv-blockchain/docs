This guide sets up an API that charges for access using HTTP 402 Payment Required, the standard HTTP status code reserved for exactly this. You'll build a server that gates specific routes behind a price, and a client that pays automatically when it hits one.

**Time:** ~25 minutes
**Prerequisites:** Node.js 22+, basic Express.js, a general sense of how Bitcoin-style transactions work

## What You'll Build

<CardGroup cols={2}>
  <Card title="Server" icon="server">

  </Card>
  <Card title="Client" icon="laptop-code">
    A `fetch` wrapper that catches 402 responses, pays automatically, and retries, with no user prompt mid-request.

The flow: the client requests a resource, the server replies 402 with the price, the client signs a payment and retries, and the server grants access.

## Before You Begin

- Node.js 22 or newer
- npm or pnpm
- A BRC-100 wallet for both the server identity and the client
- A private key for the server's identity

## Step 1: Set Up the Two Projects

The server and client are separate projects, since in a real deployment they typically run on different machines:


## Step 2: Build the Server

In the server project, create `server.ts`:

```typescript
import express from 'express'
import bodyParser from 'body-parser'
import { createPaymentMiddleware } from '@bsv/402-pay/server'
import { ServerWallet } from '@bsv/simple/server'
import dotenv from 'dotenv'

dotenv.config()

async function setupServer() {
  // 1. Initialize the server's own wallet
  const wallet = await ServerWallet.create({
    privateKey: process.env.SERVER_PRIVATE_KEY!,
    network: 'main',
    storageUrl: 'https://store-us-1.bsvb.tech'
  })

  // 2. Create the payment-gating middleware
  const paymentMiddleware = createPaymentMiddleware({
    wallet,
    calculatePrice: path => {
      // Price per route
      if (path === '/api/premium') return 1000 // 1000 satoshis
      if (path === '/api/free') return 0 // Free
      return 100 // Default: 100 satoshis
    }
  })

  // 3. Build the app
  const app = express()
  app.use(bodyParser.json())
  app.use(paymentMiddleware)

  // 4. Define routes
  app.get('/api/free', (req, res) => {
    res.json({
      message: 'Free content',
      paid: false
    })
  })

  app.get('/api/premium', (req, res) => {
    res.json({
      message: 'Premium content, paid!',
      paid: true,
      satoshisPaid: req.payment?.satoshisPaid || 0,
      sender: req.payment?.senderIdentityKey
    })
  })

  return app
}

async function main() {
  const app = await setupServer()
  const port = process.env.PORT || 3000

  app.listen(port, () => {
    console.log(`Payment server running on http://localhost:${port}`)
    console.log('- GET /api/free: No payment required')
    console.log('- GET /api/premium: Requires 1000 satoshis')
  })
}

main().catch(console.error)
```

The middleware does two things in order: it checks whether the route needs payment and whether a valid payment was already provided, then it lets the route handler run only if the route is free or the payment checked out.

## Step 3: Understand the 402 Response

When the client requests a paid route without having paid yet, the server replies with status 402 and the payment details it needs. The middleware handles this automatically:

- It calculates the price using `calculatePrice()`.
- It returns a 402 status if nothing has been paid yet.
- It includes two headers the client needs: `x-bsv-sats` (how much is owed) and `x-bsv-server` (the server's identity key, used to derive the payment address).

## Step 4: Build the Paying Client

In the client project, create `client.ts`:

```typescript
import { create402Fetch } from '@bsv/402-pay/client'
import { WalletClient } from '@bsv/sdk'
import dotenv from 'dotenv'

dotenv.config()

export async function setupPaymentClient() {
  // Wallet used to sign payments
  const wallet = new WalletClient()

  // A fetch wrapper that pays automatically on a 402
  const fetch402 = create402Fetch({
    wallet,
    cacheTimeoutMs: 30 * 60 * 1000 // Cache paid content for 30 minutes
  })

  return fetch402
}
```

`create402Fetch()` gives you back something you can use exactly like `fetch`, except it catches 402 responses, signs a payment, retries the request with payment attached, and caches the result so you don't pay twice for the same thing.

## Step 5: Make Requests

Create `requests.ts` in the client project:

```typescript
export async function accessFreeContent(fetch402: any) {
  const response = await fetch402('http://localhost:3000/api/free')
  const data = await response.json()

  console.log('Free content:', data)
  return data
}

export async function accessPremiumContent(fetch402: any) {
  // Pays automatically if a 402 comes back
  const response = await fetch402('http://localhost:3000/api/premium')
  const data = await response.json()

  console.log('Premium content:', data)
  return data
}

export async function clearPaymentCache(fetch402: any) {
  // Reset the cache between sessions
  fetch402.clearCache()
  console.log('Payment cache cleared')
}
```

When `fetch402('/api/premium')` runs, here's what actually happens behind the scenes:

<Steps>
  <Step title="Request sent, no payment">
    The client calls the endpoint with no payment attached.
  </Step>
  <Step title="Server replies 402">
    The response includes `x-bsv-sats: 1000` and `x-bsv-server`.
  </Step>
  <Step title="Client derives a payment address">
    A fresh nonce and timestamp are generated, then used to derive the payment address with BRC-29.
  </Step>
  <Step title="Client signs and retries">
    A payment transaction is created, signed, and the request is retried with payment headers attached.
  </Step>
  <Step title="Server validates and grants access">
    Once the payment checks out, the response is returned and cached for next time.
  </Step>
</Steps>

## Step 6: Build Payment Headers Manually (Advanced)

For a custom flow where you don't want `create402Fetch` managing everything, you can construct the headers yourself:

```typescript
import { constructPaymentHeaders } from '@bsv/402-pay/client'

export async function manualPayment(
  wallet: any,
  serverUrl: string,
  satoshis: number,
  serverIdentityKey: string
) {
  const headers = await constructPaymentHeaders(wallet, serverUrl, satoshis, serverIdentityKey)

  const response = await fetch(serverUrl, { headers })
  return response
}
```

This gives you direct control over five headers:

| Header | What it carries |
| --- | --- |
| `x-bsv-beef` | The payment transaction proof, base64-encoded BEEF |
| `x-bsv-sender` | Your identity public key |
| `x-bsv-nonce` | A random 8-byte derivation prefix |
| `x-bsv-time` | A Unix millisecond timestamp |
| `x-bsv-vout` | The output index, usually `0` |

```typescript
  const wallet = await ServerWallet.create({
    privateKey: process.env.SERVER_PRIVATE_KEY!,

  const paymentMiddleware = createPaymentMiddleware({
    wallet,
    calculatePrice: path => {
      if (path === '/api/premium') return 1000
      if (path === '/api/free') return 0
      return 100
    }
  })

  const app = express()
  app.use(bodyParser.json())
  app.use(paymentMiddleware)

  app.get('/api/free', (req, res) => {
    res.json({ message: 'Free content', paid: false })

  app.get('/api/premium', (req, res) => {

    console.log('Server on http://localhost:3000')

main().catch(console.error)
```

Client `main.ts`:

```typescript
import { create402Fetch } from '@bsv/402-pay/client'
import { WalletClient } from '@bsv/sdk'

async function main() {
  const wallet = new WalletClient()

  const fetch402 = create402Fetch({
    wallet,
    cacheTimeoutMs: 30 * 60 * 1000
  })

  console.log('Accessing free content...')
  let response = await fetch402('http://localhost:3000/api/free')
  let data = await response.json()
  console.log('Free:', data)

  console.log('\nAccessing premium content (will auto-pay 1000 sats)...')
  response = await fetch402('http://localhost:3000/api/premium')
  data = await response.json()
  console.log('Premium:', data)

  console.log('\nAccessing premium again (cached, no new payment)...')
  response = await fetch402('http://localhost:3000/api/premium')
  data = await response.json()
  console.log('Premium (cached):', data)
}

main().catch(console.error)
```

## Troubleshooting

<AccordionGroup>
  <Accordion title={<>"Auth middleware must run first"</>}>
    This error belongs to `@bsv/payment-express-middleware`, not `@bsv/402-pay`. The `@bsv/402-pay` middleware is independent and does not require BRC-31 auth.
  </Accordion>
  <Accordion title={<>"Wallet must implement getPublicKey() and internalizeAction()"</>}>
    The server wallet must expose an identity key and accept payment internalization. Use `ServerWallet.create()` from `@bsv/simple/server`, or another BRC-100 wallet implementation that supports both.
  </Accordion>
  <Accordion title="Payment keeps getting requested, even after paying">
    The retried request must include all five headers: `x-bsv-beef`, `x-bsv-sender`, `x-bsv-nonce`, `x-bsv-time`, and `x-bsv-vout`. `create402Fetch()` adds these automatically, so check for a missing header if you built the request manually.
  </Accordion>
  <Accordion title={<>"Transaction format error"</>}>
    The client must send the payment as base64-encoded BEEF in `x-bsv-beef`. Confirm the wallet actually returned `tx` from `createAction()`.
  </Accordion>
  <Accordion title="Timestamp must be fresh">
    `x-bsv-time` has to land within roughly 30 seconds of the server's clock. If this keeps failing, check for clock drift between client and server.
  </Accordion>
  <Accordion title="Cache timeout too long">
    A very long cache timeout risks the client reusing a stale payment for a different resource. 30 minutes is a safe default.
  </Accordion>
  <Accordion title="Replay protection">
    For `@bsv/402-pay`: the timestamp bounds how long a payment can be replayed, wallet internalization validates the transfer, and a separate atomic store admits each transaction ID exactly once. Its default store is bounded but local to the process, so inject a shared, durable store if you run more than one process or node. The wallet's optional `isMerge` flag is defense in depth only, it isn't part of the public BRC-100 result shape.

    For `@bsv/payment-express-middleware`: inject a durable, atomic transaction-ID replay store yourself in any multi-process deployment. Its derivation prefix is not a replay database on its own.

    If payment processing fails after the wallet has already started work, the middleware returns `503` without issuing a new challenge. Treat that as ambiguous, reconcile the transaction before asking the client to pay again, rather than assuming the payment never happened.
  </Accordion>
</AccordionGroup>
