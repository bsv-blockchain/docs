title: Gate an API behind payments
description: Charge for API routes with HTTP 402 Payment Required, using an Express middleware that prices a route and a fetch wrapper that pays from a BRC-100 wallet and repeats the request.
---

**HTTP 402 payment gating** lets an API charge per request, with no accounts and no API keys. The server answers a priced route with status 402 and the price, and the client pays from its BRC-100 wallet and repeats the request. The `@bsv/402-pay` package implements both sides of the exchange that [BRC-121](https://bsv.brc.dev/payments/0121) defines.

## Before you begin

To follow this guide, have these ready:

- Node.js 22 or newer.
- BSV Desktop on testnet with some test coins, for the client, as set up in [Send a payment from a web app](/docs/get-started/quick-start-browser/).

## Set up the gated API

Build a server that charges for one route, then a client that pays for it.

### Charge for a route

Follow these steps to charge 1000 satoshis for one route of an Express API and leave another route free:

<Steps>
  <Step title="Install the packages">

    ```bash Install
    npm install express @bsv/sdk @bsv/402-pay @bsv/wallet-toolbox
    npm install -D tsx @types/express @types/node
    ```

  </Step>
  <Step title="Create the server key">

    The key is the identity of the server wallet, and the payments belong to it. Generate it once:

    ```bash Generate a key
    node -p "require('@bsv/sdk').PrivateKey.fromRandom().toHex()"
    ```

    Save the output in a `.env` file as `SERVER_PRIVATE_KEY=<the key>`.

  </Step>
  <Step title="Create the server wallet and gate the route">

    Create `server.ts`:

    ```ts server.ts
    import express from 'express'
    import { Setup, type SetupEnv } from '@bsv/wallet-toolbox'
    import { createPaymentMiddleware, type PaymentResult } from '@bsv/402-pay/server'

    declare module 'express-serve-static-core' {
      interface Request {
        payment?: PaymentResult
      }
    }

    // Setup reads only `chain` from env when you pass rootKeyHex
    const env = { chain: 'test' } as SetupEnv

    async function main() {
      const { wallet } = await Setup.createWalletSQLite({
        env,
        rootKeyHex: process.env.SERVER_PRIVATE_KEY!,
        filePath: './server-wallet.sqlite',
        databaseName: 'gate-api'
      })

      const app = express()

      app.get('/api/free', (req, res) => {
        res.json({ message: 'Free content' })
      })

      app.get('/api/premium', createPaymentMiddleware({ wallet, calculatePrice: () => 1000 }), (req, res) => {
        res.json({
          message: 'Premium content',
          satoshisPaid: req.payment?.satoshisPaid,
          paidBy: req.payment?.senderIdentityKey,
          txid: req.payment?.txid
        })
      })

      app.listen(3000, () => console.log('Server on http://localhost:3000'))
    }

    main().catch(console.error)
    ```

    `Setup.createWalletSQLite` builds the server wallet on a local SQLite file, so no remote storage server is involved, and the wallet keeps what it receives in `server-wallet.sqlite`. `calculatePrice` returns the price in satoshis, and a price of `0` or `undefined` lets the request through.

    Put the middleware on the route instead of pricing request paths in one global function. Express serves `/api/premium/` and `/API/premium` from the same route, and a price table keyed by `req.path` does not match them, so they would be served without payment.

  </Step>
  <Step title="Start the server">

    ```bash Start
    npx tsx --env-file=.env server.ts
    ```

  </Step>
  <Step title="Request the priced route">

    ```bash Request
    curl -i http://localhost:3000/api/premium
    ```

    The response is a 402 with an empty body and two headers, `x-bsv-sats: 1000` and `x-bsv-server`, the identity key of the server wallet.

  </Step>
</Steps>

The server serves `/api/free` to anyone and answers `/api/premium` with a 402 until a payment of 1000 satoshis arrives.

### Pay for a route

With the server answering 402, the client needs a wallet that signs the payment and a `fetch` that pays and repeats the request:

<Steps>
  <Step title="Install the packages in the client project">

    ```bash Install
    npm install @bsv/sdk @bsv/402-pay
    npm install -D tsx @types/node
    ```

  </Step>
  <Step title="Create the paying fetch and request the route">

    Create `client.ts`:

    ```ts client.ts
    import { WalletClient } from '@bsv/sdk'
    import { create402Fetch } from '@bsv/402-pay/client'

    async function main() {
      const fetch402 = create402Fetch({ wallet: new WalletClient('auto', 'localhost:3000') })

      const response = await fetch402('http://localhost:3000/api/premium')
      console.log(response.status, await response.json())
    }

    main().catch(console.error)
    ```

    The second argument of `WalletClient` is the originator, the name BSV Desktop shows in the payment request. A Node script needs one to reach BSV Desktop.

  </Step>
  <Step title="Run the client and authorize the payment">

    ```bash Run
    npx tsx client.ts
    ```

    BSV Desktop opens a **Spending Request** for `localhost`, labeled `BRC-121 web payment`, with the price plus a network fee that depends on the size of the transaction, for example 1,057 satoshis for a price of 1000. Select **Authorize**. The client then prints `200` and the premium content, with `satoshisPaid`, `paidBy` and the `txid` of the payment.

  </Step>
  <Step title="Cache paid responses">

    The client does not cache by default. Set `cacheTimeoutMs` on `create402Fetch` to reuse a paid `GET` response for that long, and call `fetch402.clearCache()` to force a new payment.

    ```ts
    const fetch402 = create402Fetch({
      wallet: new WalletClient('auto', 'localhost:3000'),
      cacheTimeoutMs: 30 * 60 * 1000
    })
    ```

  </Step>
</Steps>

The wrapper reads the price from the 402, pays from the wallet to an address derived from the server key, and sends the request again with five `x-bsv-*` headers. When the server rejects that payment, `fetch402` returns the second 402 instead of throwing, so the status of the response tells whether the payment was accepted.

## Customize and deploy

Once the basic flow works, adapt how the client pays and prepare the server for real traffic.

### Pay without confirming each request

To let a script or a server pay without a request for each payment, turn off the spending permission of BSV Desktop:

<Tabs>
  <Tab title="BSV Desktop 3.1.1">

    <Steps>
      <Step>Open **Settings**, and under **Network & connections** select **Advanced settings**.</Step>
      <Step>Scroll to **Permissions Configuration** and turn off **Require permission for spending wallet funds** in **General Settings**.</Step>
      <Step>Select **Save Permissions Configuration** and reload the app.</Step>
    </Steps>

  </Tab>
  <Tab title="BSV Desktop 2.9.9">

    <Steps>
      <Step>Open **Settings**, and under **Permissions Configuration** select **Show Advanced Settings**.</Step>
      <Step>Scroll to **General Settings** and turn off **Require permission for spending wallet funds**.</Step>
      <Step>Select **Save Permissions Configuration** and reload the app.</Step>
    </Steps>

  </Tab>
</Tabs>

<Callout type="warning">
  With this permission off, any process on the machine that reaches the local API of BSV Desktop can spend from the wallet without asking, because that API has no authentication. Use a wallet only for this purpose, with little funds.
</Callout>

With the permission off, the client pays without opening a request. The permission is on or off, and BSV Desktop has no limit per payment.

### Pay without the fetch wrapper

A client that does not use `fetch`, such as a service worker or another HTTP library, builds the payment headers itself:

<Steps>
  <Step title="Read the price and the server key from the 402">
    Take the amount from `x-bsv-sats` and the key from `x-bsv-server` on the 402 response.
  </Step>
  <Step title="Build the headers and repeat the request">

    ```ts
    import { constructPaymentHeaders } from '@bsv/402-pay/client'

    const headers = await constructPaymentHeaders(wallet, url, satoshis, serverIdentityKey)
    const response = await fetch(url, { headers })
    ```

  </Step>
</Steps>

The function returns these five headers:

| Header | Value |
| --- | --- |
| `x-bsv-beef` | The payment transaction as base64 BEEF |
| `x-bsv-sender` | The identity public key of the client |
| `x-bsv-nonce` | Base64 of 8 random bytes, the derivation prefix |
| `x-bsv-time` | A Unix timestamp in milliseconds, which the server accepts within 30 seconds of its own clock |
| `x-bsv-vout` | The index of the payment output, `0` |

### Prepare the API for production

Before the API serves more than one process or leaves your machine, check these points:

- Serve the API over HTTPS. The client refuses a plain `http://` URL unless the host is `localhost`, `127.0.0.1` or `[::1]`, and it sends the payment with `redirect: 'manual'`, so request the final HTTPS address instead of one that redirects.
- Share one replay store between processes. The server accepts each payment transaction once. The default store lives in the memory of one process and holds 100,000 entries. With more than one process, pass `replayStore`, an object whose `claim(txid, expiresAt)` method is atomic and shared:

  ```ts
  createPaymentMiddleware({ wallet, calculatePrice: () => 1000, replayStore })
  ```

- Keep the clocks in sync. The server rejects a payment whose timestamp differs from its own clock by more than 30 seconds, in either direction. Keep both clocks on NTP, or change the window with `paymentWindowMs`.

A 503 means the wallet or the replay store failed after the payment started, for example because the store is full. The middleware sends no new 402 then, so that the client does not pay twice, and the payment may already be credited to the wallet.

## Troubleshooting

<AccordionGroup>
  <Accordion title={<>"No wallet available over any communication substrate"</>}>
    The client reached no wallet because a Node script needs an originator to connect to BSV Desktop. Create the wallet with `new WalletClient('auto', 'localhost:3000')`, and keep BSV Desktop open and unlocked.
  </Accordion>
  <Accordion title={<>"A valid wallet instance is required"</>}>
    The middleware got an object that is not a BRC-100 wallet, such as a `ServerWallet` from `@bsv/simple`. Pass the wallet from `Setup.createWalletSQLite`, or `serverWallet.getClient()` for a `ServerWallet`.
  </Accordion>
  <Accordion title="The client gets a 402 again after it paid">
    The server rejected the payment, and `fetch402` returns that second 402 instead of throwing. The usual causes are a timestamp more than 30 seconds off the server clock, an output below the price, and a payment that was already used.
  </Accordion>
  <Accordion title="The server answers 503 with an empty body">
    The wallet or the replay store failed after the payment started, and the middleware hides the error. To read it, wrap `wallet.internalizeAction` in a `try` and `catch` and log the error. A `ServerWallet` on a remote storage server for another network fails here with `The tx parameter must be valid AtomicBEEF`, so use local storage as in this guide.
  </Accordion>
  <Accordion title={<>"Wallet storage returned invalid settings."</>}>
    `ServerWallet.create` rejects a storage server that answers an empty `dbtype`, as the Go testnet storage server does. Use a wallet on local storage with `Setup.createWalletSQLite`.
  </Accordion>
  <Accordion title={<>"Payment requests require HTTPS except on the local loopback interface"</>}>
    The client refuses to send a payment over plain `http://` to any host except `localhost`, `127.0.0.1` and `[::1]`. Serve the API over HTTPS and request that address.
  </Accordion>
  <Accordion title={<>"Cannot read properties of undefined (reading 'fileExists')" with ts-node</>}>
    `ts-node` 10.9.2 fails with TypeScript 7, the version that `npm install -D typescript` installs today. Run the scripts with `tsx`, as in this guide.
  </Accordion>
</AccordionGroup>
