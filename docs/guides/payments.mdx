**HTTP 402 payment gating** lets an API charge per request, with no accounts and no API keys, which fits when each request should be paid as it happens. In this guide you build an Express API with one free route and one priced route, then a client that pays the price from [BSV Desktop](https://desktop.bsvb.tech/) and gets the content. The server and the client are separate Node projects, and only the middleware is something you add to an API you already have.

## Before you begin

You need Node.js 22 or newer, and a testnet wallet in BSV Desktop with some test coins for the client. [Send a payment from a web app](/docs/get-started/quick-start-browser/) shows how to set one up.

## How it works

The `@bsv/402-pay` package implements both sides of the exchange that [BRC-121](https://bsv.brc.dev/payments/0121) defines. Two programs and a wallet take part:

- The server is an Express API. A middleware, `createPaymentMiddleware`, prices a route, and the server has its own wallet on a local SQLite file that receives the payments.
- The client is a Node script. `create402Fetch` wraps `fetch`, asks BSV Desktop to sign the payment, and repeats the request.

<PaymentGatingFlow />

The client pays from the wallet to an address derived from the server key, and sends the payment in five `x-bsv-*` headers.

## Set up the gated API

Build a server that charges for one route and a client that pays for it, each in its own new folder.

### Charge for a route

Follow these steps in an empty folder for the server to charge 1000 satoshis for one route of an Express API and leave another route free:

<Steps>
  <Step title="Install the packages">

    ```bash Install
    npm install express @bsv/sdk @bsv/402-pay @bsv/wallet-toolbox
    npm install -D tsx @types/express @types/node
    ```

    `express` serves the API, `@bsv/402-pay` provides the middleware, `@bsv/wallet-toolbox` builds the server wallet and `@bsv/sdk` generates the key in the next step.

  </Step>
  <Step title="Create the server key">

    In the same folder, generate the key. It is the identity of the server wallet, and the payments belong to it. Generate it once:

    ```bash Generate a key
    node -p "require('@bsv/sdk').PrivateKey.fromRandom().toHex()"
    ```

    Save the output in a `.env` file in the server folder as `SERVER_PRIVATE_KEY=<the key>`.

  </Step>
  <Step title="Create the server wallet and gate the route">

    Create `server.ts` in the server folder:

    ```ts server.ts
    import express from 'express'
    import { Setup, type SetupEnv } from '@bsv/wallet-toolbox'
    import { createPaymentMiddleware, type PaymentResult } from '@bsv/402-pay/server'

    declare module 'express-serve-static-core' {
      interface Request {
        payment?: PaymentResult
      }
    }

    // Setup reads only `chain` from env when you pass rootKeyHex
    const env = { chain: 'test' } as SetupEnv

    async function main() {
      const { wallet } = await Setup.createWalletSQLite({
        env,
        rootKeyHex: process.env.SERVER_PRIVATE_KEY!,
        filePath: './server-wallet.sqlite',
        databaseName: 'gate-api'
      })

      const app = express()

      app.get('/api/free', (req, res) => {
        res.json({ message: 'Free content' })
      })

      app.get('/api/premium', createPaymentMiddleware({ wallet, calculatePrice: () => 1000 }), (req, res) => {
        res.json({
          message: 'Premium content',
          satoshisPaid: req.payment?.satoshisPaid,
          paidBy: req.payment?.senderIdentityKey,
          txid: req.payment?.txid
        })
      })

      app.listen(3000, () => console.log('Server on http://localhost:3000'))
    }

    main().catch(console.error)
    ```

    `Setup.createWalletSQLite` builds the server wallet on a local SQLite file, so no remote storage server is involved, and the wallet keeps what it receives in `server-wallet.sqlite`. `calculatePrice` returns the price in satoshis, and a price of `0` or `undefined` lets the request through.

    Put the middleware on the route instead of pricing request paths in one global function. Express serves `/api/premium/` and `/API/premium` from the same route, and a price table keyed by `req.path` does not match them, so they would be served without payment.

  </Step>
  <Step title="Start the server">

    In the server folder, start it:

    ```bash Start
    npx tsx --env-file=.env server.ts
    ```

    The terminal prints the line below and stays busy, so the next step uses a second terminal.

    ```text Output
    Server on http://localhost:3000
    ```

  </Step>
  <Step title="Request the priced route">

    In a second terminal, request the route without paying:

    ```bash Request
    curl -i http://localhost:3000/api/premium
    ```

    The 402 comes from the middleware of your server, with an empty body and two headers that the client needs. The usual Express headers are left out here:

    ```text Output
    HTTP/1.1 402 Payment Required
    x-bsv-sats: 1000
    x-bsv-server: <identity key of the server wallet>
    Content-Length: 0
    ```

  </Step>
</Steps>

### Pay for a route

With the server answering 402, create a second folder for the client, with a wallet that signs the payment and a `fetch` that pays and repeats the request:

<Steps>
  <Step title="Install the packages in the client folder">

    ```bash Install
    npm install @bsv/sdk @bsv/402-pay
    npm install -D tsx @types/node
    ```

    `@bsv/402-pay` provides `create402Fetch` for the client, and `@bsv/sdk` provides `WalletClient`, which connects to BSV Desktop. The client does not need the server packages.

  </Step>
  <Step title="Create the paying fetch and request the route">

    Create `client.ts` in the client folder:

    ```ts client.ts
    import { WalletClient } from '@bsv/sdk'
    import { create402Fetch } from '@bsv/402-pay/client'

    async function main() {
      const fetch402 = create402Fetch({ wallet: new WalletClient('auto', 'localhost:3000') })

      const response = await fetch402('http://localhost:3000/api/premium')
      console.log(response.status, await response.json())
    }

    main().catch(console.error)
    ```

    The second argument of `WalletClient` is the originator, the name BSV Desktop shows for your app. A Node script cannot reach the wallet without one.

  </Step>
  <Step title="Run the client and authorize the payment">

    In the client folder, with the server still running, run it:

    ```bash Run
    npx tsx client.ts
    ```

    BSV Desktop opens a **Spending Request** for `localhost`, labeled `BRC-121 web payment`, with the price plus a network fee that depends on the size of the transaction, for example 1,057 satoshis for a price of 1000. Click **Authorize**. The client then prints the status and the premium content, with the amount, the identity key of the client and the transaction id of the payment:

    ```text Output
    200 {
      message: 'Premium content',
      satoshisPaid: 1000,
      paidBy: '<identity key of the client wallet>',
      txid: '<transaction id of the payment>'
    }
    ```

  </Step>
  <Step title="Cache paid responses">

    The client does not cache by default. Set `cacheTimeoutMs` on `create402Fetch` to reuse a paid `GET` response for that long, and call `fetch402.clearCache()` to force a new payment.

    ```ts
    const fetch402 = create402Fetch({
      wallet: new WalletClient('auto', 'localhost:3000'),
      cacheTimeoutMs: 30 * 60 * 1000
    })
    ```

  </Step>
</Steps>

## Customize and deploy

Once the basic flow works, adapt how the client pays and prepare the server for real traffic.

### Pay without confirming each request

To let a script or a server pay with nobody at the screen to click **Authorize**, turn off the spending permission of BSV Desktop:

<Steps>
  <Step>
    Open **Settings**, and under **Network & connections** click **Advanced settings**.

    <Frame>
      <img src="/images/gate-api/01-advanced-settings.png" alt="The Settings page of BSV Desktop with the Advanced settings entry under Network and connections" />
    </Frame>
  </Step>
  <Step>
    Scroll to **Permissions Configuration**, click **Show Advanced Settings** and turn off **Require permission for spending wallet funds** in **General Settings**. The toggle is on by default.

    <Frame>
      <img src="/images/gate-api/02-spending-permission.png" alt="The General Settings of the Permissions Configuration with the Require permission for spending wallet funds toggle and the Save Permissions Configuration button" />
    </Frame>
  </Step>
  <Step>Click **Save Permissions Configuration** and reload the app.</Step>
</Steps>

<Callout type="warning">
  With this permission off, any process on the machine that reaches the local API of BSV Desktop can spend from the wallet without asking, because that API has no authentication. Use a wallet only for this purpose, with little funds.
</Callout>

### Pay without the fetch wrapper

A client that cannot use `create402Fetch`, such as a service worker or another HTTP library, builds the payment headers itself. This example reads the price and the server key from the 402, builds the headers and sends the paid request, and the `fetch` calls stand for the HTTP client you use. The code goes inside an async function, like `main` in `client.ts`:

<Steps>
  <Step title="Read the price and the server key from the 402">

    ```ts
    const first = await fetch(url)
    const satoshis = Number(first.headers.get('x-bsv-sats'))
    const serverIdentityKey = first.headers.get('x-bsv-server')!
    ```

    `x-bsv-sats` holds the price in satoshis and `x-bsv-server` the identity key of the server wallet, the same two headers that the `curl` output showed.

  </Step>
  <Step title="Build the headers and repeat the request">

    ```ts
    import { WalletClient } from '@bsv/sdk'
    import { constructPaymentHeaders } from '@bsv/402-pay/client'

    const wallet = new WalletClient('auto', 'localhost:3000')
    const headers = await constructPaymentHeaders(wallet, url, satoshis, serverIdentityKey)
    const response = await fetch(url, { headers })
    ```

    `constructPaymentHeaders` asks the wallet for a payment of `satoshis` to an address derived from `serverIdentityKey`. The headers it returns go on the repeated request, and a 200 means the server accepted the payment.

  </Step>
</Steps>

The function returns these five headers:

| Header | Value |
| --- | --- |
| `x-bsv-beef` | The payment transaction as base64 BEEF |
| `x-bsv-sender` | The identity public key of the client |
| `x-bsv-nonce` | Base64 of 8 random bytes, the derivation prefix |
| `x-bsv-time` | A Unix timestamp in milliseconds, which the server accepts within 30 seconds of its own clock |
| `x-bsv-vout` | The index of the payment output, `0` |

The paid request then looks like this, with the long values shortened:

```http
GET /api/premium HTTP/1.1
x-bsv-beef: <base64 BEEF of the payment transaction>
x-bsv-sender: <66 hex characters, the identity key of the client>
x-bsv-nonce: q83vEjRWeJA=
x-bsv-time: 1791979200000
x-bsv-vout: 0
```

### Prepare the API for production

Before the API serves more than one process or leaves your machine, check these points:

- Serve the API over HTTPS. The client sends the payment with `redirect: 'manual'`, so request the final HTTPS address instead of one that redirects.
- Share one replay store between processes. The server accepts each payment transaction once, and the default store lives in the memory of one process and holds 100,000 entries. With more than one process, pass `replayStore`, an object whose `claim(txid, expiresAt)` method is atomic and shared:

  ```ts
  createPaymentMiddleware({ wallet, calculatePrice: () => 1000, replayStore })
  ```

- Keep the clocks in sync with NTP, or change the window with `paymentWindowMs`.

To adopt this in a real project, add `createPaymentMiddleware` to the routes you want to charge for in your own Express API, and keep `SERVER_PRIVATE_KEY` in your secret store and the SQLite file on storage that survives restarts.

## Troubleshooting

<AccordionGroup>
  <Accordion title="Client cannot find BSV Desktop">
    The client fails with `No wallet available over any communication substrate`. A Node script cannot connect to BSV Desktop without an originator, so pass one as the second argument of `WalletClient`, as in `client.ts`, and keep BSV Desktop open and unlocked.
  </Accordion>
  <Accordion title="Middleware rejects the wallet you passed">
    The `wallet` option of `createPaymentMiddleware` takes a BRC-100 wallet, the object that `Setup.createWalletSQLite` returns in this guide. Any other object makes the server stop with `A valid wallet instance is required`. A `ServerWallet` from `@bsv/simple` is one of those objects, so pass `serverWallet.getClient()` for it.
  </Accordion>
  <Accordion title="Client gets a 402 again after paying">
    The middleware of your server rejected the payment, and `fetch402` returns that second 402 instead of throwing. The usual causes are a timestamp more than 30 seconds off the server clock, an output below the price, and a payment that was already used.
  </Accordion>
  <Accordion title="Server answers 503 with an empty body">
    The middleware of your server answers this when the wallet or the replay store failed after the payment started, and it hides the error. To read it, wrap `wallet.internalizeAction` in a `try` and `catch` and log the error. The middleware sends no new 402 after a 503, so that the client does not pay twice, and the payment may already be credited to the wallet.
  </Accordion>
  <Accordion title="Client refuses to pay over plain http">
    The client stops with `Payment requests require HTTPS except on the local loopback interface`. It sends a payment over `http://` only to `localhost`, `127.0.0.1` and `[::1]`, so serve the API over HTTPS and request that address.
  </Accordion>
  <Accordion title="Server crashes when started with ts-node">
    The crash shows `Cannot read properties of undefined (reading 'fileExists')`. `ts-node` 10.9.2 fails with TypeScript 7, the version that `npm install -D typescript` installs today. Run the scripts with `tsx`, as in this guide.
  </Accordion>
</AccordionGroup>
